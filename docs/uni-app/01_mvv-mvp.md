## 0. この文書の読み方と用語

この文書は、アプリを作り始める前に「何のために・誰のために・何を・どう稼ぐか」を固めるためのものです。
コードは1行も出てきません。開発は、ここで決めたことを土台に進めます。

| 用語 | 意味（かみくだき） |
|---|---|
| **MVV** | Mission（何のために存在するか）、Vision（どんな未来を目指すか）、Value（迷ったときの判断基準）の3点セット |
| **MVP** | Minimum Viable Product。「最小限だけど、ちゃんと使える最初の版」。全部盛りにせず、いちばん大事な体験だけを先に出す |
| **ストリーク** | 連続達成日数。多くの習慣アプリで使われるが、途切れたときに自己嫌悪を生みやすい |
| **リテンション** | 継続率。「入れた人のうち、7日後・30日後も使っている人の割合」 |
| **ローカル保存** | データをサーバーに送らず、スマホの中だけに保存すること。ログイン不要・個人情報の扱いが軽くなる |
| **アプリ内課金（IAP）** | App Store / Google Play を通してアプリの中で売る仕組み。売上の15〜30%が手数料として引かれる |
| **ストア審査** | Apple / Google がアプリを公開前にチェックする工程。ルール違反があると差し戻される |
| **PWA** | ブラウザで開くけれどアプリのようにホーム画面に置ける Web サイト。ストア不要だが機能に制限あり |

## 1. ひとことで言うと

> **シーズーの「うに」と一緒に、続けたいことを毎日ちょっとずつ続けるアプリ。**
> **続けた分だけ、うにと、行き場のない動物たちが元気になる。**

既存の習慣アプリとの違いは3つです。

1. **叱らない。** 休んだ日に責められない。ストリークが途切れても記録は消えない
2. **相棒が実在する。** キャラクターは架空ではなく、本当に暮らしているシーズー「うに」
3. **お金の行き先が見える。** 収益の一部が保護動物の支援に使われ、その内訳を毎月公開する

## 2. MVV（案）

### Mission（存在理由）

> **「続ける」を、がんばりではなく、暮らしの気持ちよさに変える。**

習慣化アプリの多くは「自分を管理する道具」です。このアプリは「そばに誰かがいるから、なんとなく今日もやる」を作ります。
管理ではなく、同居。

### Vision（目指す未来）

> **習慣を続けた時間が、自分と、そばにいる命を育てる循環をつくる。**

ユーザーが1日1タップする → うにがよろこぶ → その積み重ねが寄付になる → 保護された動物が新しい家に行く。
この循環が回っている状態を目指します。

### Value（判断の軸）— 迷ったらここに戻る

| # | バリュー | 具体的にどういうことか |
|---|---|---|
| 1 | **叱らない** | 未達成の日に赤や「×」を出さない。通知で急かさない。ストリークは「連続」ではなく「累計」を主役にする |
| 2 | **小さく、確かに** | 1日の操作は1タップで終わる。機能を足すときは「1タップが増えないか」を必ず問う |
| 3 | **お金を隠さない** | 寄付額・養育費・運営費の内訳を毎月公開する。「一部を寄付」ではなく「何%をどこへ」と書く |
| 4 | **静かな上質さ** | 画面は落ち着いた配色と余白で作る。派手な演出やランキングで煽らない |

### エーテルアーキの「4つの要素」との関係

ブランドの軸である **形・質・光・時** を、アプリの中では控えめにこう対応させます。
（ユーザーに向けて語るのではなく、設計するときの内部指針として使います）

| 要素 | アプリでの現れ方 |
|---|---|
| 形 | 習慣そのもの。「何を、どのくらいの頻度で」という輪郭を決める |
| 質 | 1回1回の達成の手ざわり。うにの反応が「作業感」を消す |
| 光 | 達成した瞬間の小さな明るさ。画面の演出ではなく、うにの表情で表す |
| 時 | 続けた時間の可視化。カレンダーと累計で「積もった時間」を見せる |

## 3. 誰のためのアプリか

### 主ターゲット

- **20〜40代、習慣アプリを何度か挫折した人**
- ストリークが途切れてアプリごと消した経験がある
- 犬・動物が好き。SNS で保護犬の投稿を見ると足が止まる
- 「がんばる系」のUIに疲れている

### 副ターゲット

- 保護犬・保護猫の活動を応援したいが、寄付先を探す・手続きするのが面倒な人
- 「うに」自体のファン（SNS で育てる前提）

### 既存アプリとの位置づけ

| アプリ | 強み | このアプリが取る距離 |
|---|---|---|
| Streaks / Habitify 系 | 高機能・統計が豊富 | 機能で勝負しない。統計は最小限 |
| Habitica 系 | ゲーム化で楽しい | ゲーム要素は「うにの反応」だけに絞る。レベル・敵・罰は入れない |
| みんチャレ 系 | 仲間の目で続く | 他人を介さない。相手はうにだけ |
| Forest / Finch 系 | 育成型で癒やし | 一番近い。違いは「実在の犬」と「実際の寄付」 |

## 4. うにのキャラクター設計

### 役割

**相棒であって、監督ではない。**

- ユーザーが習慣をこなす → うにがよろこぶ、散歩に出る、おやつを食べる
- 休んだ日 → うにも寝ている。責めない。次の日にまた普通に迎える
- 続いた日 → うにの「ごきげん度」が上がる。ただし下がっても罰はない

### 絵柄：実写の写真をもとにした「ポケコロ風」2Dアバター（決定）

実写のうにの写真を何枚か預かり、それを参考にポケコロのような**2.5頭身のデフォルメアバター**として描き起こします。
実写そのものは「月1回の『うに便り』（後述の課金特典）」で使い、イラストの世界と現実のうにをつなぎます。

#### 参考にする「ポケコロ風」の要素

| 要素 | どうするか |
|---|---|
| 頭身 | 2〜2.5頭身。頭が大きく、体は小さい |
| 目 | 大きく丸い。ハイライト（光の点）を1〜2つ |
| 線 | 細めの輪郭線。色は黒ではなく濃い茶色（やわらかく見える） |
| 塗り | 平らな塗り＋うすい影1段。グラデーションは使わない |
| 色 | 実写のうにの毛色をそのまま採用。背景はエーテルアーキのオフホワイト系で静かに |
| 着せ替え前提 | 体・顔・アクセサリーをレイヤー（層）に分けて描く。後で服やリボンを足せるように |

**注意**: 「ポケコロ」はココネ社のサービス名で、そのキャラクターや画面をまねることはできません。参考にするのは「頭身・線・塗りの雰囲気」までにとどめ、うに独自のデザインとして描きます。

#### 実写から取り出す「うにらしさ」（写真を受け取ったら確認する項目）

- 毛色の配置（顔の白い部分、耳や背中の色）
- 目と鼻の距離、鼻ぺちゃの度合い
- 耳の垂れ方、毛の長さ（トリミング直後か伸びているか）
- いつも着けているもの（リボン、ヘアゴム、首輪）
- 決まったポーズやクセ（首をかしげる、舌が出る、など）

#### 制作の流れ

1. 写真を `docs/uni-app/reference/`（非公開。リポジトリには入れない）に集める
2. 上の項目を書き出し、「うにの特徴シート」を作る
3. 生成AIで下絵を数パターン出し、方向性を1つ選ぶ
4. 選んだ方向で、正面「ふつう」の1枚を清書する（自分で手直し、または外注）
5. 「ふつう」をもとに残り4表情を差分で作る
6. iPhone 用に 1x / 2x / 3x の PNG（または SVG）で書き出す

### 最初に必要な表情（5パターン）

| 状態 | 出る場面 | セリフ例 |
|---|---|---|
| ふつう | ホーム画面の待機 | 「きょうは なにする？」 |
| うれしい | 習慣を1つ達成 | 「やったね」 |
| ごきげん | その日の習慣を全部達成 | 「ぜんぶ おわった。さんぽ いこ」 |
| ねむい | 夜、未達成のまま | 「ねるまえに 1こだけ、どう？」 |
| おやすみ | 前日に達成なし（翌朝） | 「おはよ。きょうも いっしょに」 |

セリフのトーン：短い、ひらがな多め、敬語なし、命令しない。「〜しなきゃ」「〜できてない」は使わない。

## 5. MVP の機能範囲

### 必ず入れる（v1.0）

| # | 機能 | 中身 | バリューとの対応 |
|---|---|---|---|
| 1 | 習慣の登録 | 名前・頻度（毎日／曜日指定）・リマインド時刻。**最大5つまで** | 小さく、確かに |
| 2 | 今日のチェック | ホーム画面で1タップ。取り消しも1タップ | 小さく、確かに |
| 3 | うにの反応 | 5表情＋短いセリフ。達成状況で切り替わる | 質・光 |
| 4 | 記録カレンダー | 月表示。達成した日は色がつく。未達成の日は**何も表示しない**（×を出さない） | 叱らない |
| 5 | 累計表示 | 「これまでに○回」「うにと歩いた距離 ○km」（1チェック＝100m 換算など） | 時 |
| 6 | リマインド通知 | 端末内で完結するローカル通知。1日1回まで。文面はうにのセリフ | 叱らない |
| 7 | ローカル保存 | ログイン不要。データはスマホの中だけ。書き出し（バックアップ）機能つき | お金を隠さない（個人情報を持たない） |
| 8 | 寄付についての説明画面 | 「収益の一部がどこにどう使われるか」を1画面で | お金を隠さない |

### 次に入れる（v1.1〜）

- **サポーターパス**（課金。第6章参照）
- **うに便り**：月1回の実写写真＋寄付レポート（サポーター向け）
- ホーム画面ウィジェット（今日の残り＋うにの表情）
- 着せ替え・季節の背景

### 当面やらない（意図的に）

- アカウント登録・クラウド同期（個人情報の管理責任と、アカウント削除機能の実装義務が発生するため）
- 友達機能・ランキング・SNS共有（他人との比較は「叱らない」に反する）
- 広告（画面の静けさを壊す。収益はサポーターパスで立てる）
- ストリークの強調（累計を主役にする）
- AI によるアドバイス（v1では不要。うには喋りすぎない）

## 6. マネタイズと寄付の設計

### 結論：「寄付を売る」のではなく「商品を売って、会社が寄付する」

ここは **ストアのルールに直結する** ので、最初に構造を固めます。

**Apple のガイドライン（3.2.1 / 3.2.2）では、アプリ内で「寄付」を集められるのは承認済みの非営利団体だけです。**
営利事業者であるエーテルアーキのアプリで「この購入は寄付です」「寄付する」ボタンを置くと、審査で差し戻されるか、最悪の場合は公開停止の対象になります。Google Play も同様の考え方です。

そのため、設計は次の形にします。

```
ユーザーが買うもの   ： サポーターパス（デジタル商品）
                      → 着せ替え・うに便り・詳細統計 などの「機能」の対価
会社がやること       ： サポーターパス売上の X% を保護動物団体へ寄付し、毎月レポートを公開
アプリ内の表現       ： 「サポーターパスの売上の X% は、保護動物の支援に使われます」
                      （「寄付する」「募金」というボタン・文言は置かない）
```

- 「養育費」は会社の経費なので、売上から普通に使えます。ただし**公開レポートでは「うにの養育費」と「寄付」を分けて書く**ことで、透明性を保ちます
- ユーザーが金額を選んで直接寄付する機能は、アプリには入れません。やるなら Web サイト側で団体の寄付ページへ**外部リンク**する形にします（これも v1 では見送り）

### 日本の法律で気にする点（専門家の最終確認が必要な論点）

| 論点 | 何を気にするか |
|---|---|
| 景品表示法 | 「売上の X% を寄付」と書いたら、実際にその通りに寄付し、証拠（領収書等）を残す。「一部を寄付」のような曖昧表現は避ける |
| 寄付先の名称・ロゴ掲載 | 団体名を出すなら、**事前に団体の許諾**をとる。無断で「○○に寄付します」とは書かない |
| 特定商取引法 | ストア経由の販売なら Apple / Google が販売者情報を担うが、Web 版で直接売る場合は事業者表示が必要 |
| 税務 | 法人からの寄付は損金算入の上限がある。認定NPO法人への寄付は枠が広がる。税理士に確認 |

### 価格と配分（案）

| 項目 | 案 | 備考 |
|---|---|---|
| サポーターパスの形 | **買い切り 1,000円前後** | まずは買い切り。サブスクは必須表記が多く、審査項目も増えるので v2 以降に検討 |
| 寄付の割合 | **手数料控除後の売上の 30%（決定）** | 「X%」は目立つ数字なので、続けられる数字を選ぶ。10% だと弱く、50% だと運営が続かない |
| 残りの使い道 | うにの養育費・運営費（ストア年会費、サーバー、イラスト外注） | レポートで内訳を出す |
| レポート | 毎月、アプリ内と Web サイトで公開 | 「今月の寄付：○円 → ○○団体」「うにの養育費：○円」 |

### 寄付先（決定）と、公開前に確認すること

| 寄付先 | 運営 | 30% の内訳（案） |
|---|---|---|
| **リベ大アニマルレスキュー** | リベラルアーツ大学（両学長）の関連事業として運営される保護活動 | 15% |
| **ピースワンコ・ジャパン** | 認定NPO法人ピースウィンズ・ジャパンの保護犬事業 | 15% |

内訳は「半分ずつ」を基本にし、レポートでは団体ごとの金額を分けて書きます。

**公開前に必ず確認すること**（アプリに団体名を出す前に済ませる）:

1. **法人格の確認**: 各団体が「認定NPO法人」か「一般社団法人」か等で、寄付の税務上の扱いが変わる。ピースウィンズ・ジャパンは認定NPO法人。リベ大アニマルレスキューは運営主体の法人格を公式サイトで確認する
2. **法人からの寄付の受け入れ可否と、振込先・手続き**
3. **団体名をアプリとレポートに掲載する許諾**（メールで依頼し、返信を保管）
4. **「売上の一部を寄付」型の表現に団体側のガイドラインがあるか**（大きな団体は「支援企業向けの表記ルール」を持っていることがある）

許諾が取れるまでは、アプリ内では「保護犬・保護猫の支援団体」と書き、団体名は出しません。

## 7. 技術の選び方（iOS 専用が決まったので見直し）

### 選択肢

iOS のみで公開すると決まったため、選択肢は実質2つに絞られます。

| 案 | 何ができるか | 長所 | 弱点 |
|---|---|---|---|
| **A. SwiftUI ＋ SwiftData ＋ StoreKit 2（Apple 標準）← 推奨** | iPhone 専用のアプリを Apple 純正の道具だけで作る | 通知・ウィジェット・課金がすべて標準部品で済み、外部サービスへの依存がゼロ。動作が軽い。審査で引っかかる要素が少ない | **Mac と Xcode が必須**。Android に出せない（今回は不要） |
| B. Expo（React Native）＋ TypeScript | 1つのコードから iOS / Android / Web を出せる | **Mac がなくてもクラウドで iPhone 用ビルドを作れる**。将来 Android を足しやすい | 課金・ウィジェットで外部部品（RevenueCat 等）に頼る。アプリ容量がやや大きい |

### 決定：A（SwiftUI）。Mac と Xcode が手元にあることを確認済み

iOS 専用なら、Apple 標準の道具で作るのがいちばん少ない部品数で済みます。
ウィジェットと通知（ガイドライン 4.2 対策）も標準で作れ、課金も StoreKit 2 だけで完結します。

B（Expo）は、将来 Android 版を出したくなったときの選択肢として残しておきます。

### v1 の技術構成（A 案）

| 役割 | 使うもの | かみくだき |
|---|---|---|
| アプリ本体 | SwiftUI | 画面と動きを作る Apple 標準の土台 |
| データ保存 | SwiftData | スマホ内の小さなデータベース（ログイン不要・サーバー不要） |
| 通知 | UserNotifications | 端末内で鳴らすリマインド |
| ウィジェット | WidgetKit | ホーム画面に「今日の残り＋うにの表情」を置く |
| 課金（v1.1〜） | StoreKit 2 | App Store の課金を扱う標準部品。「復元」ボタンも標準で作れる |
| 配布 | Xcode → TestFlight → App Store Connect | 内々に配る → 審査 → 公開 |
| デザイン | Figma または本リポジトリの `docs/uni-app/design/` にスケッチ | 先に画面を絵で決める |

### バンドル ID（決定: `com.gonation.unikoro`）

バンドル ID とは「Apple の中でアプリを一意に識別する住所」で、**一度決めると変更できません**。
アプリ名（ストアに表示される名前）とは別物です。

- 元になるドメインとして **gonation.com** を新規取得する。「Gonation」はドメインとバンドル ID にだけ使い、ストアやアプリ内に表示する発行元はエーテルアーキのまま
- ドメインの空き状況はこの企画書の作成環境からは確認できなかった。**レジストラ（お名前.com、Cloudflare Registrar など）で空きを確かめてから取得する**
- gonation.com が取れなかった場合の代替: `gonation.app` ／ `gonation.jp` ／ `gonationapp.com`。その場合はバンドル ID もそれに合わせて `app.gonation.unikoro` のように直す（取得前なら変更は自由）
- 技術的にはドメインを持っていなくてもバンドル ID は登録できるが、他人がそのドメインを取ると紛らわしいので、ドメイン取得→バンドル ID 登録の順にする

### 開発中のルール（Claude Code へ）

- 進捗・処理内容は**日本語で**表示・説明する（ユーザーの指定）

## 10. ストア公開に向けて、今のうちに押さえる3点

公開作業のフルリストは実装が進んでから整理します。今の設計判断に関わるものだけ挙げます。

1. **「寄付」という言葉をアプリ内の購入導線に使わない**（第6章）。後から文言を直すだけでは済まず、商品設計ごと変わるため、いま決める
2. **ログイン不要にしておく**と、アカウント削除機能の実装義務（ガイドライン 5.1.1(v)）と審査用デモアカウントの提出が不要になる。v1 はこの形で通す
3. **通知とウィジェットのどちらかは v1 に入れる**。機能が薄い小規模アプリはガイドライン 4.2 で弾かれやすい。通知は v1 に含めてあり、SwiftUI ならウィジェットも標準部品で足せる

iOS 専用にしたことで、Google Play 側の準備（開発者登録、別のスクリーンショット、別の審査）は不要になりました。
Apple Developer Program（年間 約1.5万円）への登録だけが必要です。名義は個人か法人（エーテルアーキ）かで審査に出す書類が変わるので、登録前に決めます。

課金を入れる v1.1 の時点で「復元ボタン」「有料 App 契約の締結」「課金アイテムをビルドと同時提出」が必要になります。そのタイミングで公開準備を一通り整理します。

## 12. アプリ名（決定: うにコロ）

**「うにコロ」に決定しました。** 「うに」＋「コロ（コロコロした丸さ、犬の呼び名の定番）」で、ポケコロ風の丸いアバターと響きが合います。
英字表記は **Unikoro**（プロジェクト名・バンドル ID に使用）。

### サブタイトル案（App Store で名前の下に出る30文字以内の一文）

| 案 | ねらい |
|---|---|
| うにコロと、きょうもひとつ。 | 「1日1つでいい」を最初に伝える |
| 叱らない習慣アプリ。相棒はシーズー。 | 検索語「習慣アプリ」を含めつつ、差別化を一言で |

### 公開前に確認すること

- 商標検索（特許情報プラットフォーム J-PlatPat）で「うにコロ」「ウニコロ」を確認する。出願するかは任意だが、他社の登録があれば名前を変える必要がある

---

以下は、決定に至るまでの候補と基準の記録です。


### 名前に求めること

| 条件 | 理由 |
|---|---|
| 「うに」が入っている、または呼びやすい | うに自体をブランドにする。SNS での発信と直結させる |
| 4〜6文字、ひらがな中心 | ホーム画面の下に表示される名前は短くないと省略される（目安 6文字前後） |
| App Store で検索してかぶらない | 同名アプリがあると埋もれる。候補が絞れたら実際に検索して確かめる |
| 「習慣」「タスク」を名前に入れない | 管理っぽさが出て「叱らない」に反する。習慣の意味はサブタイトルで補う |
| 声に出して恥ずかしくない | 人にすすめるときに口に出せる名前が広まる |

### 候補（3つの方向）

**方向A: うにとの暮らしをそのまま名前に**

| 候補 | 読み | ニュアンス |
|---|---|---|
| うにと | uni to | 「うにと（いっしょに）」。短く、あとに何でも続けられる |
| きょうもうに | kyō mo uni | 毎日開く感じ。通知の文面にもそのまま使える |
| うにのひ | uni no hi | 「うにの日」。1日の単位を意識させる |
| うにとまいにち | uni to mainichi | 意味が明快。少し長い |

**方向B: 造語・愛称**

| 候補 | 読み | ニュアンス |
|---|---|---|
| うにっき | unikki | うに＋日記。記録アプリだと伝わる |
| うにぽ | unipo | ポケコロ風の丸さに合う。意味は持たせず響きで |
| うにまる | unimaru | 丸い見た目そのもの。同名の店やキャラが多い可能性あり |

**方向C: 英字（海外展開を見据える場合）**

| 候補 | 読み | ニュアンス |
|---|---|---|
| Uni | ユニ | 最短。ただし「大学」「ユニクロ」等と検索でかぶりやすい |
| Uniday | ユニデイ | うに＋day。日本語話者にも読める |
| with Uni | ウィズ ユニ | 「うにと」の英語版 |

### 私のおすすめ

**「うにと」** を第一候補にします。理由は、通知や画面のセリフが「うにと、さんぽ」「うにと、1こだけ」のように自然につながり、サブタイトルを「うにと、きょうも ひとつ。」のように置けるからです。
第二候補は **「うにっき」**。記録アプリだと一目で伝わり、検索でもかぶりにくい響きです。

### 決め方（提案）

1. 上の候補から気になるものを3つ選ぶ（候補にないものを足してもよい）
2. その3つを App Store で検索し、同名・類似のアプリを確認する
3. iPhone のホーム画面に仮のアイコンと名前を置いてみて、しっくりくるものにする
