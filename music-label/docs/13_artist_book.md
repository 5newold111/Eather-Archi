# 13. アーティスト台帳（スプレッドシート）

アーティストの情報は、**1 冊のスプレッドシート（アーティスト台帳）を正本**にする。
オーナーが書き足した内容を、機械が毎週読み込んで「今週どんなテーマの曲を作るか」「どの曲を参考にするか」を決める。

- 場所：`music-label/artists.xlsx`（Excel・Numbers・Google スプレッドシートで開ける）
- 機械がやるのは **提案まで**。台帳に「状態＝提案」の行を足すだけで、採用はオーナーが決める
- 2026-10-08 に、それまでの 17 組は `templates/archive/2026-10-08/` へ移した（白紙）。本体 5 枠の新しい提案は `proposals/2026-10-08/`

## この管理方法でよい理由と、気をつけること

| よいところ | 気をつけること（仕組みで手当て済み） |
|---|---|
| 1 組の情報が 1 か所にまとまり、いつでも書き足せる | 1 つのセルに何でも書くと機械が読めない → **項目ごとに列を分け、出来事は 1 行 1 件**にした |
| 人生年表・近況を足すほど、曲のテーマが増える | 提案と採用が混ざる → **状態の列**（提案／採用／保留／却下）で分ける |
| 表なので並べて比べやすい（5 組の違いが見える） | 実在の名前が作曲の指示文に混ざる → **実名は『影響』『参考曲の候補』のタブだけ**。機械も読むときに伏せる |
| Google スプレッドシートにすればスマホからも書ける | 書き間違いで制作が止まる → 読み込みは毎回記録を残し、前の設定書の機械用の項目（デビュー週・Persona など）は消さない |

## タブ（シート）と書くこと

| タブ | 1 行の単位 | 主な列 |
|---|---|---|
| 使い方 | — | この台帳の決まりごと |
| アーティスト | 1 組 | ID・状態・レーベル・軸・名前・構成・場面・出身・拠点・文化・強み・デビューの経緯・ファンのつき方・人間関係・作詞作曲の担当・普段の話題・音楽以外の表現・価値観・今後・今の章・英語の紹介文 |
| メンバー | 1 人 | 名前・担当・年齢・誕生日・性別・出身地・ルーツ・言葉・身長・体重・髪（色・長さ・型）・ファッション・性格・価値観・話し方（訛り・口癖・語尾）・家族・休日・音楽以外の表現・友人・好き嫌い（こと・言葉・色・食べ物） |
| 人生年表 | 1 つの時期 | 誰・年齢（から/まで）・西暦・場所・暮らしと学校・周りにいた人・出来事・気持ち・歌の種にする（○） |
| デビューの経緯 | 1 つの段階 | 時期・場（路上・ライブハウス・配信・大会など）・やったこと・反応とファンの数・転機 |
| 傷・タトゥー | 1 つ | 誰・種類・体の場所・いつ・図柄・込めた想い（無い人は「なし」と理由） |
| 影響 | 1 作品 | 誰・種類（音楽・本・絵・映画・言葉）・題名・作者・受け取ったもの（**実名を書いてよいタブ**） |
| 歌の種 | 1 つのアイデア | 種ID・時期・気持ち・情景・視点・アイデア・言葉の候補 |
| 歌詞の試作 | 1 曲 | 種ID・仮タイトル・サビ（英語）・1 番の書き出し・日本語の意味 |
| 近況 | 1 つの出来事 | 日付・出来事・気持ち・歌にする（○） |
| 参考曲の候補 | 1 曲 | 曲名・アーティスト・年・この組が選ぶ理由・借りたい要素・入手・解析（**実名を書いてよいタブ**） |
| 声と曲づくり | 1 組 1 行 | 声の性別・声域・音域（音名）・裏声・得意な歌い方・毎曲の癖 3 つ・旋律・ジャンル・楽器・BPM・構成・毎曲必ず・使わない・歌詞のテーマ・言語・トーン・相性のよい組 |
| 見た目 | 1 組 1 行 | 空間・光・素材・色・カメラ・ジャケットの決まり・顔を見せない方法・ロゴ・写真の質感と構図 |
| 変更の提案 | 1 つの変更 | タブ・項目・今の値・提案する値・理由（方針転換などで機械が足す） |

- 組と行をつなぐのは **ID**（英小文字と `_`。例 `nao_easterly`）。メンバーは **メンバーID**
- 複数の値は「、」か改行で区切る（例：好きな色 → `朝の水色、生成り`）。○ は「はい」
- 列の見出しは変えない（機械は見出しの文字で読む）。列の順番を入れ替えるのは大丈夫

## 状態の列

| 状態 | 意味 | 機械の扱い |
|---|---|---|
| 提案 | 機械が足した案 | 読むだけ。制作には使わない |
| 採用（または空欄） | 使う | 次の読み込みから制作に使う |
| 保留 | あとで決める | 使わない |
| 却下 | 使わない | 使わない（消さずに残すと、同じ案を出しにくくなる） |
| 反映済み | 変更の提案を書き込んだ | — |

オーナーが自分で書いた行は、状態を空欄のままでよい（採用として扱う）。

## 流れ

```
提案（機械）──→ 台帳に「提案」の行 ──→ オーナーが読む（proposals/<組>.md）
                                          │ 採用 / 保留 / 却下
                                          ▼
          artist_book.py pull（毎週火曜 6:00 に自動）──→ 設定書 templates/artists/<ID>.json
                                          │
                     毎週のブリーフ：今週の歌のもと（近況 → 歌の種）＋ 参考曲（その組の候補を優先）
```

### 今週のテーマの決まり方

1. 『近況』で **歌にする ○** が付いた出来事のうち、まだ歌にしていない新しいもの
2. 無ければ『歌の種』の上から、まだ使っていないもの（試作の歌詞があれば、そのサビを土台にする）
3. 全部使ったら、いちばん前に使った種へ戻る

選ばれた瞬間はブリーフの `life_moment` に入り、Claude は「その人がその時に感じたこと」として歌詞の核を書く。
人生の要約（拠点・家族・話し方・最近の出来事など）も一緒に渡す。**実在の名前は伏せて渡す**。

### 参考曲の決まり方

『参考曲の候補』で採用した曲を **正規に入手して解析**（`out/references/` → `analyze_track.py`）すると、
その組の割り当てで優先される（重み 1.8 倍、借りたい要素の枠なら 3 倍）。入手したら『入手』に ○。
管理画面（`out/dashboard.html`）に、採用したのにまだ入手していない曲が出る。

### その時々の想いを足していく

- 思いついたら『近況』に 1 行（日付・出来事・気持ち・歌にする ○）。次の火曜から使われる
- 毎月 1 日に、機械が各組の **来月の近況と歌の種** を提案する（返事待ちが残っている組には足さない）
- 年表の出来事に ○ を付けると、その時期も歌の候補として Claude に渡る

## コマンド

| やりたいこと | コマンド |
|---|---|
| 台帳を作る（最初の 1 回） | `python3 scripts/artist_book.py init` |
| 提案の JSON を確かめる | `python3 scripts/artist_book.py check proposals/2026-10-08` |
| 提案を台帳に入れる | `python3 scripts/artist_book.py import-json proposals/2026-10-08` |
| 読みやすい資料にする | `python3 scripts/artist_book.py render`（→ `proposals/<ID>.md`） |
| 1 組の提案をまとめて採用 | `python3 scripts/artist_book.py adopt nao_easterly`（却下・保留にした行はそのまま） |
| 設定書に反映 | `python3 scripts/artist_book.py pull`（火曜 6:00 に自動） |
| 台帳の状態 | `python3 scripts/artist_book.py status` |
| 新しい組を Claude に提案させる | `python3 scripts/artist_book.py propose --label 本体 --axis 光 --note "日本とアメリカのハーフ"` |
| 来月の近況と歌の種を提案させる | `python3 scripts/artist_book.py propose-update --all`（毎月 1 日に自動） |
| 採用した変更の提案を書き込む | `python3 scripts/artist_book.py apply-changes` |

鍵（ANTHROPIC_API_KEY）が無いときの `propose` は、Claude に渡す依頼文を `out/artist_book/` に書き出して止まる。

## 機械が持つ項目（台帳に書かない）

設定書のうち次の項目は機械が管理し、`pull` でも消さない：
デビュー週（`debut_week`）・制作の頻度（`cadence`）・名前の確認結果・Suno の Persona ID・配信先の ID・
コンセプトの世代と転換の履歴・Blender ファイルの場所・声の合成の比率・エネルギー曲線・トレンド言語の設定。

- **名前を変えたら**、名前の確認（`check_names.py`）をやり直す扱いになる
- **場面か見た目を変えたら**、コンセプトの世代が上がり、写真の撮り直し（`generate_visuals.py --kind reshoot`）を案内する
- **方針転換**（伸び悩み）は、台帳の組では『変更の提案』に行が足されるだけ。採用 → `apply-changes` → `pull` で反映
- **デビュー**：新しく採用した組は、毎月 1 日の確認で 4 週間以上あとの「1 日のある週」に予約される。
  本体 5 組をまとめて決めるときは `python3 scripts/debut.py --month 2026-12`

## Google スプレッドシートで使うとき（任意）

Excel のままでも全部動く。スマホから書きたい・共同で書きたいときだけ。

1. Google ドライブで `artists.xlsx` を開き、「ファイル → Google スプレッドシートとして保存」（タブ名と見出しはそのまま）
2. Google Cloud（YouTube と同じプロジェクトでよい）で **Google Sheets API** を有効にする
3. 「IAM と管理 → サービス アカウント」で作成 → 「鍵 → 鍵を追加 → JSON」→ ダウンロードした JSON を
   **リポジトリの外**（例 `~/.config/etherarchi/sheets.json`）に置く
4. スプレッドシートの「共有」で、サービスアカウントのメールアドレス（`…@….iam.gserviceaccount.com`）を **編集者** に追加
5. 鍵を入れる（URL の `/d/` と `/edit` の間が ID）

```
python3 scripts/set_key.py ARTIST_BOOK_GSHEET_ID
python3 scripts/set_key.py GOOGLE_SERVICE_ACCOUNT_FILE     # 例 /Users/<you>/.config/etherarchi/sheets.json
pip3 install cryptography
python3 scripts/artist_book.py status                       # 読めるか確認
```

この 2 つが .env にあると、全部のコマンドが Google スプレッドシートを読む（無ければ `artists.xlsx`）。

## 記録と予備

- `pull` のたびに台帳の中身を `out/artist_book/snapshots/<日時>.json` に保存（間違えて消しても戻せる）
- `artists.xlsx`・`proposals/`・記録は、毎晩 R2 に予備保管（`backup_r2.py`）
