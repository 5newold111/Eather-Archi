# 13. アーティスト管理表（スプレッドシート）

アーティストの情報は、**1 冊のスプレッドシート（アーティスト管理表）を正本**にする。
オーナーが書き足した内容を、機械が毎週読み込んで「今週どんなテーマの曲を作るか」「どの曲を参考にするか」を決める。

- 正本：**Google スプレッドシートの「アーティスト管理表」**（オーナーが共有したもの）。`.env` に `ARTIST_BOOK_GSHEET_ID` を入れると機械が読む
- 見本と予備：`music-label/artists.xlsx`（同じデザインの Excel。Google の設定が無いときはこちらを読む）
- 機械がやるのは **提案まで**。管理表に「状態＝提案」を足すだけで、採用はオーナーが決める
- 2026-10-08 に、それまでの 17 組は `templates/archive/2026-10-08/` へ移した（白紙）。新しい 5 組の提案は `proposals/2026-10-08/`
- 2026-10-09 に **軸（形・質・光・時・自）は廃止** した。アーティストは軸を持たない

## この管理方法でよい理由と、気をつけること

| よいところ | 気をつけること（仕組みで手当て済み） |
|---|---|
| 1 組の情報が 1 か所にまとまり、いつでも書き足せる | 1 つのセルに何でも書くと機械が読めない → **項目ごとに欄を分け、出来事は 1 行 1 件**にした |
| 人生年表・近況を足すほど、曲のテーマが増える | 提案と採用が混ざる → **状態の列**（提案／採用／保留／却下）で分ける |
| 表なので並べて比べやすい（5 組の違いが見える） | 実在の名前が作曲の指示文に混ざる → **実名は『影響』『参考曲の候補』のタブだけ**。機械も読むときに伏せる |
| Google スプレッドシートにすればスマホからも書ける | 書き間違いで制作が止まる → 読み込みは毎回記録を残し、前の設定書の機械用の項目（デビュー週・Persona など）は消さない |

## タブ（シート）と書くこと

タブには 2 つの向きがある。

- **縦型**（1 列 = 1 組・1 人）：項目が多いタブ。A 列に項目が並び、組を横に並べて見比べられる。■ の帯で項目をまとめている。
  新しい組は右の空いた列に書く
- **横型**（1 行 = 1 件）：出来事や作品を何件でも足していくタブ。1 行目が見出し

| タブ | 向き | 1 件の単位 | 主な項目 |
|---|---|---|---|
| はじめに | — | — | 状態の色・タブの案内（件数つき）・書き方のきまり |
| アーティスト | 縦 | 1 組 | 名前・状態・ID／■基本（読み方・名前の由来・構成・レーベル・性別・生年月日（現在の年齢）・曲で使用するメインの楽器）／■生まれと暮らし（出身・拠点・文化）／■活動（場面・強み・デビューの経緯・ファンのつき方・音楽以外の表現）／■人と関係（力関係・作詞・作曲・普段の話題）／■考え方といま（価値観・今後・今の章・風景の言葉）／■公開用（英語の紹介文） |
| メンバー | 縦 | 1 人 | 名前・状態・どの組か／■基本（担当・年齢・誕生日・性別・出身地・ルーツ・言葉）／■見た目（身長・体重・髪・ファッション）／■内面／■話し方（訛り・口癖・語尾）／■暮らしと人（家族・友人・休日・表現）／■好きなもの／■嫌いなもの |
| 人生年表 | 横 | 1 つの時期 | 誰・年齢（から/まで）・西暦・場所・暮らしと学校・周りにいた人・出来事・気持ち・歌の種にする（○） |
| デビューの経緯 | 横 | 1 つの段階 | 時期・場（路上・ライブハウス・配信・大会など）・やったこと・反応とファンの数・転機 |
| 傷・タトゥー | 横 | 1 つ | 誰・種類・体の場所・いつ・図柄・込めた想い（無い人は「なし」と理由） |
| 影響 | 横 | 1 作品 | 誰・種類（音楽・本・絵・映画・言葉）・題名・作者・受け取ったもの（**実名を書いてよいタブ**） |
| 歌の種 | 横 | 1 つのアイデア | 種ID・時期・気持ち・情景・視点・アイデア・言葉の候補 |
| 歌詞の試作 | 横 | 1 曲 | 種ID・仮タイトル・サビ（英語）・1 番の書き出し・日本語の意味 |
| 近況 | 横 | 1 つの出来事 | 日付・出来事・気持ち・歌にする（○） |
| 参考曲の候補 | 横 | 1 曲 | 曲名・アーティスト・年・この組が選ぶ理由・借りたい要素・入手・解析（**実名を書いてよいタブ**） |
| 声と曲づくり | 縦 | 1 組 | 声の性別・声域・音域（音名）・裏声・得意な歌い方・毎曲の癖 3 つ・旋律・ジャンル・楽器・BPM・構成・毎曲必ず・使わない・歌詞のテーマ・言語・トーン・相性のよい組 |
| 見た目 | 縦 | 1 組 | 空間・光・素材・色・カメラ・ジャケットの決まり・顔を見せない方法・ロゴ・写真の質感と構図 |
| 変更の提案 | 横 | 1 つの変更 | タブ・項目・今の値・提案する値・理由（方針転換などで機械が足す） |

- 組と行をつなぐのは **ID**（英小文字と `_`。例 `nao_easterly`）。メンバーは **メンバーID**
- 複数の値は「、」か改行で区切る（例：好きな色 → `朝の水色、生成り`）。○ は「はい」
- 見出し（項目名）の文字は変えない（機械は見出しの文字で読む）。列や行の順番を入れ替えるのは大丈夫
- 機械は向きを自動で見分けて読む（古い横型の表もそのまま読める）

### 見た目のきまり

| 色・形 | 意味 |
|---|---|
| タブの色 | 茶＝人物（アーティスト・メンバー・年表・デビュー・傷・影響）／緑＝歌づくり（歌の種・試作・近況・参考曲・声と曲づくり）／青＝見た目／灰＝変更の提案 |
| 状態のチップ | 黄＝提案・緑＝採用・灰＝保留・赤＝却下・青＝反映済み（却下の行は文字が薄く、取り消し線） |
| 組の色 | 組ごとに 1 色。縦型の名前の行と、横型のアーティストID の欄が同じ色になる |
| ■ の帯 | 縦型タブの項目のまとまり |
| 灰色の小さな文字 | 機械用の ID |
| プルダウン | 状態・構成・性別・声の性別／声域・言語・歌詞の作り方・影響の種類・傷の種類・○ の欄は一覧から選べる |
| 見出しのメモ | 書き方の説明がある項目は、見出しにカーソルを置くと出る |

## 状態

| 状態 | 意味 | 機械の扱い |
|---|---|---|
| 提案 | 機械が足した案 | 読むだけ。制作には使わない |
| 採用（または空欄） | 使う | 次の読み込みから制作に使う |
| 保留 | あとで決める | 使わない |
| 却下 | 使わない | 使わない（消さずに残すと、同じ案を出しにくくなる） |
| 反映済み | 変更の提案を書き込んだ | — |

オーナーが自分で書いた行は、状態を空欄のままでよい（採用として扱う）。

## 流れ

```
提案（機械）──→ 管理表に「提案」を足す ──→ オーナーが読む（proposals/<日付>/<組>.md）
                                          │ 採用 / 保留 / 却下
                                          ▼
          artist_book.py pull（毎週火曜 6:00 に自動）──→ 設定書 templates/artists/<ID>.json
                                          │
                     毎週のブリーフ：今週の歌のもと（近況 → 歌の種）＋ 参考曲（その組の候補を優先）
```

### 今週のテーマの決まり方

1. 『近況』で **歌にする ○** が付いた出来事のうち、まだ歌にしていない新しいもの
2. 無ければ『歌の種』の上から、まだ使っていないもの（試作の歌詞があれば、そのサビを土台にする）
3. 全部使ったら、いちばん前に使った種へ戻る

選ばれた瞬間はブリーフの `life_moment` に入り、Claude は「その人がその時に感じたこと」として歌詞の核を書く。
人生の要約（拠点・家族・話し方・最近の出来事など）も一緒に渡す。**実在の名前は伏せて渡す**。

### 参考曲の決まり方

『参考曲の候補』で採用した曲を **正規に入手して解析**（`out/references/` → `analyze_track.py`）すると、
その組の割り当てで優先される（重み 1.8 倍、借りたい要素の枠なら 3 倍）。入手したら『入手』に ○。
管理画面（`out/dashboard.html`）に、採用したのにまだ入手していない曲が出る。

### その時々の想いを足していく

- 思いついたら『近況』に 1 行（日付・出来事・気持ち・歌にする ○）。次の火曜から使われる
- 毎月 1 日に、機械が各組の **来月の近況と歌の種** を提案する（返事待ちが残っている組には足さない）
- 年表の出来事に ○ を付けると、その時期も歌の候補として Claude に渡る

## コマンド

| やりたいこと | コマンド |
|---|---|
| 管理表を作る（最初の 1 回） | `python3 scripts/artist_book.py init` |
| 今の中身のまま、デザインを整え直す | `python3 scripts/artist_book.py restyle`（Google の表なら `out/artist_book/アーティスト管理表.xlsx` に書き出す） |
| 提案の JSON を確かめる | `python3 scripts/artist_book.py check proposals/2026-10-08` |
| 提案を管理表に入れる | `python3 scripts/artist_book.py import-json proposals/2026-10-08` |
| 読みやすい資料にする | `python3 scripts/artist_book.py render`（→ `proposals/<ID>.md`） |
| 1 組の提案をまとめて採用 | `python3 scripts/artist_book.py adopt nao_easterly`（却下・保留にした行はそのまま） |
| 設定書に反映 | `python3 scripts/artist_book.py pull`（火曜 6:00 に自動） |
| 管理表の状態 | `python3 scripts/artist_book.py status` |
| 新しい組を Claude に提案させる | `python3 scripts/artist_book.py propose --label 本体 --note "日本とアメリカのハーフ"` |
| 来月の近況と歌の種を提案させる | `python3 scripts/artist_book.py propose-update --all`（毎月 1 日に自動） |
| 採用した変更の提案を書き込む | `python3 scripts/artist_book.py apply-changes` |

鍵（ANTHROPIC_API_KEY）が無いときの `propose` は、Claude に渡す依頼文を `out/artist_book/` に書き出して止まる。

## 機械が持つ項目（管理表に書かない）

設定書のうち次の項目は機械が管理し、`pull` でも消さない：
デビュー週（`debut_week`）・制作の頻度（`cadence`）・名前の確認結果・Suno の Persona ID・配信先の ID・
コンセプトの世代と転換の履歴・Blender ファイルの場所・声の合成の比率・エネルギー曲線・トレンド言語の設定。

- **名前を変えたら**、名前の確認（`check_names.py`）をやり直す扱いになる
- **場面か見た目を変えたら**、コンセプトの世代が上がり、写真の撮り直し（`generate_visuals.py --kind reshoot`）を案内する
- **方針転換**（伸び悩み）は、管理表の組では『変更の提案』に行が足されるだけ。採用 → `apply-changes` → `pull` で反映
- **デビュー**：新しく採用した組は、毎月 1 日の確認で 4 週間以上あとの「1 日のある週」に予約される。
  最初の 5 組をまとめて決めるときは `python3 scripts/debut.py --month 2026-12`

## Google スプレッドシートを正本にする

機械（Mac の定期実行）が Google の管理表を読むための設定。2 段階あり、まずは 1 だけで動く。

### 1. 読むだけ（鍵なし・5 分）

1. 管理表の「共有」で、一般的なアクセスを **「リンクを知っている全員」・閲覧者** にする
   （「編集者」にすると、リンクが漏れたときに誰でも書き換えられるので、閲覧者をすすめる）
2. Mac で ID を入れる（URL をそのまま貼ってもよい。ID だけを取り出して保存する）

```
python3 scripts/set_key.py ARTIST_BOOK_GSHEET_ID
python3 scripts/artist_book.py status        # 5 組が見えれば OK
```

これで毎週の読み込み（`pull`）は Google の表から行う。機械の提案（毎月の近況・新しい組・方針転換）は
Google の表に書けないので **`out/artist_book/pending.xlsx` に貯まる**（管理画面にも出る）。
採用したいものを Google の表に貼るか、2 の設定で直接入るようにする。

### 2. 機械も書き込む（サービスアカウント・15 分）

1. Google Cloud（YouTube と同じプロジェクトでよい）で **Google Sheets API** を有効にする
2. 「IAM と管理 → サービス アカウント」で作成 → 「鍵 → 鍵を追加 → JSON」→ ダウンロードした JSON を
   **リポジトリの外**（例 `~/.config/etherarchi/sheets.json`）に置く
3. 管理表の「共有」で、サービスアカウントのメールアドレス（`…@….iam.gserviceaccount.com`）を **編集者** に追加
4. 鍵の場所を入れる

```
python3 scripts/set_key.py GOOGLE_SERVICE_ACCOUNT_FILE     # 例 /Users/<you>/.config/etherarchi/sheets.json
pip3 install cryptography
python3 scripts/artist_book.py status
```

これで提案も採用（`adopt`）も、Google の表に直接入る。リンクの共有は「制限付き」に戻してよい。

### デザインを入れ替えるとき（中身はそのまま）

`artist_book.py restyle` が、今の中身を新しいデザインの Excel に書き出す。Google の表に入れるには：
Google スプレッドシートで **ファイル → インポート → アップロード** → そのファイルを選び → **「スプレッドシートを置換する」**。
URL と共有設定はそのまま残る。

## 記録と予備

- `pull` のたびに管理表の中身を `out/artist_book/snapshots/<日時>.json` に保存（間違えて消しても戻せる）
- `artists.xlsx`・`proposals/`・記録は、毎晩 R2 に予備保管（`backup_r2.py`）
