# 08. ビジュアル自動生成：ロゴ・顔を出さないアーティスト写真・ジャケット

## 全体像

```
デビュー時（1 組につき 1 回）
  設定書（visual / persona）＋ 参考アーティストの写真分析（解析シート I 欄）
      ↓ Claude が画像の指示文を作る
  画像 API（ChatGPT / OpenAI gpt-image-1）で候補を生成
      ├ ロゴ        × 6 候補
      └ アーティスト写真 × 8 候補（顔を隠す方法を 4 種類 × 2 枚）
      ↓ 自動チェック（規約・サイズ・顔が写っていないか）
      ↓ 採点（基準ファイル visual_criteria.json）
  最初の 5 回 → オーナーに提案して選んでもらう（判断を基準に書き戻す）
  6 回目以降 → 自動選択（基準の確信度が低いときだけ聞く）

リリース時（1 曲につき 1 回）
  ブリーフ（曲のテーマ・世界観枠の visual_web）＋ アーティストの visual.cover_series_rule
      ↓
  ジャケット × 6 候補 → 規約チェック → 採点 → 選択（同じ 5 回ルール）
```

実行：`scripts/generate_visuals.py --artist light --kind debut` / `--kind cover --brief out/briefs/....json`

## 役割分担

| 役割 | 担当 |
|---|---|
| 指示文（プロンプト）を書く、候補を採点する、基準を更新する | Claude |
| 画像を描く | ChatGPT 側の画像 API（`OPENAI_API_KEY`）。他の生成器にも差し替え可能（`--generator`） |
| 最初の 5 回の判断、基準の承認 | オーナー |

## 参考アーティストの写真を「どう参考にするか」

解析シートの I 欄（`visual_web`）に **アーティスト写真の分析**を追加した（`artist_photo`）。
参考にするのは**手法**であり、本人の姿・衣装・ロゴではない。

| 参考にする | 参考にしない |
|---|---|
| テイスト（フィルム / デジタル / 粒子感）、構図（中央 / 三分割 / 余白）、ロケーションの種類、コンセプト | 本人の顔・体型・特定の衣装・特定のマスクやキャラクター（商標・著作物） |
| 明るさ、コントラスト、色温度、背景の処理（ボケ / 均一 / 情報量） | 実在の建物・看板がそのまま分かる背景 |
| 立ち位置（カメラとの距離・人数の並び）、しぐさ（手の位置・視線の方向・歩いている / 座っている） | ポーズの完全な再現 |
| **顔を見せない方法のカテゴリ**（後述） | その方法の具体的な意匠（例：特定のバンドの被り物の形） |

画像 API には実在アーティストの名前を渡さない（本人の姿に寄る・規約違反になる）。
解析シートの形容詞に変換してから渡す。

## 顔を見せない方法のカタログ（AI アーティストとして一貫して顔を出さない）

| 方法 | 向く組 | 注意 |
|---|---|---|
| 逆光のシルエット | 光・朝・夕の組 | 輪郭だけでも個人を思わせないよう、髪型を単純に |
| 後ろ姿・振り返らない | 車内、ピアノ、机 | 最も安全。構図が単調になりやすいので背景で勝負 |
| 物で隠す（カセット、カップ、方眼紙、葉、傘） | 設定書の `visual.materials` にある物 | 商品ロゴが写り込まないように |
| 被り物・フード・帽子の影 | バンド、ラウド系 | 既存バンドの被り物の意匠に寄せない。幾何学的・抽象的に |
| 手で隠す・手だけ写す | 料理、工作、楽器 | 手だけなら顔問題が起きない |
| 俯瞰（真上から） | 机、横断歩道、朝食 | 顔が見えず、空間デザインの構図と相性がよい |
| 動きのブレ・長時間露光 | 走る、ポストロック | 顔が溶けて見えない。躍動感 |
| 窓・雨・湯気・霧のフィルター | 雨、海岸、コーヒー | 顔が判別できない程度まで曖昧に |
| 人が写らない（空間だけ） | プロデューサー、インスト | EtherArchi の強み。空間そのものがアーティスト |
| イラスト化・線画 | どの組でも | 写真と混ぜない。シリーズで統一 |

各組は設定書の `visual.face_concealment` に **主の方法 1 つ・副の方法 2 つ**を持つ。写真の候補は主 4 枚・副 2 枚ずつ。

## 規約チェック（公開前に必ず通す）

### ジャケット（Spotify / Apple Music / DistroKid 共通）
- [ ] 3000 × 3000 px、RGB、JPG または PNG、ぼやけていない
- [ ] URL・SNS アカウント名・価格・「新曲」などの宣伝文を入れない
- [ ] 文字を入れる場合は、曲名・アーティスト名と**一致**させる（違うと差し戻し）
- [ ] 第三者のロゴ・商標・キャラクター・実在人物の肖像を入れない
- [ ] 露骨な性的表現・残虐表現を入れない（入れる場合は Explicit 設定が必要になるので、入れない方針）
- [ ] 既存のジャケットの模写・コラージュをしない
- [ ] 「AI 生成」であることは配信側の申告で行う。ジャケット自体に書く必要はない

### アーティスト写真・ロゴ（Spotify for Artists / Apple / SNS）
- [ ] 実在人物に見える顔を含まない（AI 生成の顔は本人確認上も問題になるため、顔を出さない方針と一致）
- [ ] 第三者のロゴ・商標に似ていない（ロゴは必ず文字から起こす。既存ロゴの参照は禁止）
- [ ] Instagram / TikTok：露出・暴力・危険行為に見える構図を避ける。走る・運転の写真は安全に見える構図で
- [ ] 国旗・宗教的シンボル・政治的な記号を入れない

自動チェックで見られるのは「サイズ・形式・顔検出・文字の有無（OCR）」まで。残りは Claude が候補ごとに判定し、不安があれば人に回す。

## 採点と選択（`templates/visual_criteria.json`）

候補は 5 つの観点で 1〜5 点をつける。重みは基準ファイルにあり、オーナーの判断で更新される。

| 観点 | 見るもの |
|---|---|
| **一貫性** | 設定書の `visual`（空間・光・素材・色）と一致しているか。シリーズのルール（`cover_series_rule`）を守っているか |
| **象徴性** | その組を一言で表す要素が中心にあるか。ロゴなら 1 色・単純化で遠目でも分かるか |
| **場面との一致** | ジャケットなら曲のテーマ・世界観枠と合っているか |
| **安全性** | 規約チェックを全て通るか。顔が完全に隠れているか |
| **仕上がり** | 構図・明るさ・コントラスト・粒子感が参考分析の方向にあるか。文字の崩れがないか |

### 最初の 5 回はオーナーに聞く

1. 候補一覧（画像 ＋ 各候補の採点理由）を `out/visuals/<組>/<種類>/review.md` に書き出す
2. オーナーが選んだ番号と、**なぜそれを選んだか一言**を記録する
3. Claude がその理由を基準ファイルの重みと「好みのメモ」に反映する（例：「余白が多い方が好み」→ 一貫性の中に余白の項目を追加）
4. 5 回終わったら `criteria.locked = true` にし、以降は自動選択
5. 自動選択でも、1 位と 2 位の点差が 0.3 未満のときは「確信度が低い」として聞く（回数は数えない）
6. オーナーはいつでも基準ファイルを直接編集してよい

## 保存

```
covers/{artist_slug}/debut/
  logo_01..06.png, photo_01..08.png, review.md, selection.json
手元（out/visuals/）
  {artist_slug}/debut/    logo_01..06.png, photo_01..08.png, review.md, selection_logo.json, selection_photo.json
  {artist_slug}/cover/{制作週}/
                          cover_01..06.png, review.md, selection_cover.json,
                          cover_final.jpg（finalize_cover.py が 3000×3000 に拡大したもの）, cover_final.check.json
保管庫（Supabase の covers バケット）
  covers/{artist_slug}/{配信週}/cover_final.jpg   ← supabase_sync.py week --apply が上げる
```

画像生成は最大 1024×1024 なので、`finalize_cover.py` が lanczos（細部が崩れにくい拡大方法）で 3000×3000 にし、
正方形・RGB・10 MB 未満・真っ黒 / 真っ白でないことを機械で確かめる。顔・商標・文字の確認は人が登録シートで行う。

データベースには `visual_assets`（候補と選択）と `visual_decisions`（オーナーの判断と理由）を記録する。

## プロフィールの扱い

設定書の `profile`（出身・身長・体重・好きなこと・好きな食べ物・嫌いなもの・**好きな実在アーティスト**）は、
各ストアの bio と SNS の自己紹介に使う。**画像と Suno の指示文には渡さない**（`generate_visuals.py` が実名を検出すると止まる）。

## 方針転換時の撮り直し

`docs/06_growth.md` のレベル 2 転換では、設定書の `visual` を新しい場面に書き換えたあと
`generate_visuals.py --kind reshoot --pivot-reason "…"` で写真 8 枚とロゴの微調整 2 枚を作り直す。
撮り直しは**毎回オーナーに提案**する（自動選択の対象外）。顔を出さない方針と `face_concealment.never` は転換後も守る。
