# 07. 子レーベル構造：上限を設けずに増やす

## 考え方

リリース数に上限を置かない代わりに、**分野ごとに独立した子レーベル**を作り、それぞれが自分の上限（週 8 曲）を持つ。
レーベルの数を増やせば、全体の曲数は上限なく増やせる。

```
親：EtherArchi（ホールディング。音楽レーベル群の方針・技術・空間デザインを持つ）
 ├ 本体レーベル：ドライブ          ← 5 組はオーナーが決める（既存の設計）
 ├ 子レーベル A：眠り（Sleep）      ← 3 組でスタート → 月 1 組追加
 ├ 子レーベル B：朝のコーヒー（Morning）
 ├ 子レーベル C：集中（Focus）
 ├ 子レーベル D：歩く・走る（Move）
 └ （以降、体験の分野ごとに追加）
```

EtherArchi の哲学「日常の体験（コーヒーを飲む、眠る）を 4 つの要素で再定義する」に合わせ、
子レーベルは**ジャンルではなく「聴く場面（体験）」で分ける**。ジャンルの幅は各レーベルの中で少しずつ広げる。

## 各子レーベルを別アカウントにする理由と注意

| 分ける | 分けない |
|---|---|
| DistroKid アカウント（メール・支払い・配信管理） | Supabase（1 つのプロジェクトに `label_id` で分ける。クローズドなので問題ない） |
| Spotify for Artists / Apple Music for Artists のチーム | Suno（1 アカウントで Persona を分ければよい。クレジット上限で足りなくなったら追加） |
| 各 SNS アカウント、YouTube チャンネル | 解析シート・参考曲 DB（全レーベルで共有して資産にする） |
| レーベル名・ロゴ・空間の視覚言語 | 制作パイプライン（スクリプト・ルール・ブリーフの形式） |

**注意**
- 別アカウントは「配信元の分離」と「ブランドの分離」のため。**同じ曲を複数レーベルから出す、同じ人物名義で重複登録する**ことはしない（重複コンテンツはプラットフォームが最も厳しく見る）
- 各アカウントの AI 申告・公表方針は本体と同じ。「EtherArchi グループの子レーベル」であることを各レーベルのプロフィールに書く（隠さない）
- 支払い先が同じ銀行口座でも問題ない。税務上は 1 事業の複数ブランド
- DistroKid は 1 アカウントあたりのアーティスト数でプラン料金が変わる。子レーベルごとに契約が必要（年額 × レーベル数）

## 人の作業時間は減らない → 自動化の段階を分ける

| 段階 | 対象 | 選曲 | 登録 | 人の時間（週 5 曲あたり） |
|---|---|---|---|---|
| **Tier A（手動）** | 本体レーベル | 全テイクを人が聴く | 人 | 約 3.5 時間 |
| **Tier B（半自動）** | 子レーベル（立ち上げ期） | 機械が 6 テイク → 2 テイクに絞り、人が 2 つから選ぶ | 人 | 約 1.5 時間 |
| **Tier C（自動）** | 子レーベル（安定期） | 機械が 1 テイクを選ぶ。人は週に 20% を抜き取り確認 | 人 | 約 0.7 時間 |

### 機械の選曲が見るもの（Claude は音を聴けないので、数値と文字で判定する）

1. **長さ**：150〜210 秒（設定書の `drive_spec` / `scene_spec` の範囲内）
2. **音量**：-14 LUFS 付近、無音・急な音量差がない（エネルギー曲線を計測）
3. **サビの位置**：30 秒以内にエネルギーの山がある
4. **歌詞の一致**：Whisper（音声の文字起こし）でテイクの歌詞を起こし、ブリーフの歌詞と一致率を取る（Suno は言葉を崩すことがある）
5. **癖の有無**：`tics` に指定した要素（ハミング、la-la-la 等）が指定の場所に入っているか（文字起こしとエネルギー曲線で確認）
6. **終わり方**：途中で切れていない（Suno は尺で切ることがある）

上の 6 項目を満たすテイクの中から、「サビのエネルギー差が大きいもの」を選ぶ。満たすテイクがなければ再生成する。

`scripts/select_takes.py` がこの判定を行う（Tier はレーベルの設定書 `automation_tier` から読む。本体は A）。

| 項目 | 測り方 | 合格の線 |
|---|---|---|
| 長さ | 音源の長さ | 設定書の `length_sec_min`〜`max` |
| 音量 | 0.1 秒ごとの音の大きさ（RMS） | 途中の無音（中央値より 35 dB 小さい）が 1 秒未満、1 秒平均で 15 dB 以上の段差なし |
| サビの位置 | 2 秒平均の大きさが曲の上位 10% に初めて届く時刻 | `hook_within_sec` 以内（0 の組は「山と谷の差 9 dB 以下」） |
| 歌詞の一致 | 文字起こし（faster-whisper / openai-whisper、無ければ同名 .txt）とブリーフの最終歌詞の単語の一致率 | 60% 以上 |
| 癖 | 設定書の tics のうち ooh / la la / hum など文字で分かるもの | 全部入っている（必須ではなく点数に反映） |
| 終わり方 | 最後の 0.3 秒が中央値より何 dB 小さいか | 12 dB 以上（大きな音のまま切れていない） |

点数（100 点）：サビの盛り上がり 35・歌詞の一致 30・尺の中心 15・癖 10・終わりの自然さ 10。
Tier C の抜き取り確認（20%）は「週＋組」で決まる乱数なので、再実行しても同じ週が対象になる。

### 残る手作業：DistroKid 登録

DistroKid には公開 API がなく、ブラウザ自動操作は規約リスクが高い。**1 曲 5 分 × 曲数**は残る。
週 20 曲なら約 100 分。ここが実務上の天井になるので、レーベルを増やすペースはこの時間で決める。

## 子レーベルの設計（下書き）

各レーベルは `templates/labels/<slug>.json` に、方針と**代表アーティスト 3 組の下書き**がある。
3 組は「場面の中心」「少し外側」「もっと外側」の順に幅を取り、月 1 組ずつ隣の分野へ広げる。

| レーベル | 場面 | 中心の音 | 広げる方向 | 代表 3 組（下書き） |
|---|---|---|---|---|
| **Sleep（眠り）** | 眠る前・眠りの中 | アンビエント、ピアノ、環境音 | → ニューエイジ → スローなギターアンビエント → 雨音と声のハミング | ドローンのソロ／ピアノのソロ／フィールド録音のプロデューサー |
| **Morning（朝のコーヒー）** | 起きてからコーヒーを飲むまで | ジャズホップ、ボサノバ、アコースティック | → ソウル → ネオクラシカル → 朝のシティポップ | 女性ジャズボーカル／アコースティックデュオ／ローファイのプロデューサー |
| **Focus（集中）** | 仕事・勉強 | ミニマルなエレクトロニカ、ローファイビーツ | → ポストロック（インスト）→ モジュラーシンセ → 歌の少ないハウス | ビートメイカー／インストのポストロック・バンド／モジュラーシンセのソロ |
| **Move（歩く・走る）** | 散歩、ランニング、ジム | テンポの速いポップ、エレクトロ | → ドラムンベース → アフロビーツ → 走るためのロック | 高音の女性ソロ（声量型）／男女のエレクトロ・デュオ／ラウド系のバンド |

本体（ドライブ）の 5 組とは**音域・歌い方・場面が重ならない**ように下書きしてある。
下書きの名前はすべて仮（`*_TBD`）で、重複確認（`docs/03_artists.md`）が必要。

## 増やし方のルール

1. 子レーベルは **3 組でスタート**。3 か月で 1,000 再生到達率が 50% を超えたら月 1 組ずつ追加
2. 1 レーベルの週の総曲数が **8 を超えたら隔週に**切り替える（本体と同じ）。それでも足りなければ**次の子レーベルを作る**
3. 新しい子レーベルは、既存レーベルの**伸びている場面の隣**に作る（成長レポートの `up` の組が属する場面の近く）
4. レーベル間コラボ：「Sleep の組 × Drive の夜の組」のように場面が接する組同士で feat.。双方のリスナーが混ざる
5. 子レーベルの参考曲 DB は共有だが、**DNA タグで場面を分ける**（sleep / morning / focus / move / drive）

## リポジトリの構造

```
templates/
  labels/
    _template.json      ← レーベルの設定（場面・音・自動化の段階・アカウント）
    sleep.json          ← 下書き：代表 3 組を含む
    morning.json
    focus.json
    move.json
  artists/
    _template.json      ← 本体（ドライブ）の 5 組はここに（オーナーが記入）
```

`scripts/select_references.py --label sleep` で、そのレーベルの全組ぶんのブリーフを作る。
データベースは `labels` テーブルを持ち、`artists.label_id` で所属を分ける。週の上限はレーベルごと。
