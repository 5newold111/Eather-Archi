# 04. 借用ルール：似すぎを防ぎ、個性を作る

## なぜルールが要るのか

実務上、著作権で危ないのは **メロディの丸写し** と **歌詞の文章の丸写し** の 2 つです。
ただし米国では「雰囲気・グルーヴが似ている」だけで賠償が認められた判例があります（Blurred Lines 事件、2018 年）。
米国市場で収益化する以上、**1 曲から借りる要素を分散させる**のが最大の防波堤になります。

分析はどこまで細かくしても問題ありません。借りるときに分散させる——この組み合わせが基本方針です。

## ルール 1：1 曲 1 枠

1 曲を作るとき、参考曲を**枠ごとに 1 曲ずつ**割り当てます。
**歌詞の枠に使った曲は、他のどの枠にも使いません。**

| 枠 ID | 枠 | 借りるもの | 解析シートの項目 |
|---|---|---|---|
| `lyrics` | 歌詞の構造 | テーマ・起伏・韻・音節数・トーン | A |
| `worldview` | 世界観 | 舞台・内面・時代感・背景 | B |
| `instruments` | 楽器編成と音響 | 楽器リスト・環境音・エフェクト・バランス | C |
| `performance` | 演奏のクセ | 音符の置き方・奏法 | D |
| `structure` | 構成 | イントロ / アウトロ / サビの設計 | G |
| `harmony` | 和声と転調 | 転調の数・傾向・コード感 | E |
| `groove` | グルーヴとテンポ | ノリ・BPM・微妙なタイミング | F |
| `phrase` | フレーズの骨格 | リフ・決めフレーズのリズムと形（ルール 3 の変形付き） | G |
| `vocal_main` | ボーカル（6 割） | 歌い回し・表現 | H |
| `vocal_sub1` | ボーカル（2 割） | 同 | H |
| `vocal_sub2` | ボーカル（2 割） | 同 | H |

- 1 曲あたり**最大 11 曲**から 1 枠ずつ借ります
- 選び方：「そのアーティストの DNA タグに合う曲群 ＋ 今週のトレンド曲」からランダム
- ボーカルの 3 枠だけは、**音域・性別がアーティスト設定と合う曲に絞ってから**ランダムにします
- データベース側でも `brief_sources` テーブルの一意制約（同じブリーフに同じ参考曲を 2 回登録できない）で機械的に守ります
- `scripts/select_references.py` がこの割り当てを自動で行います

## ルール 2：ボーカル 6:2:2 の二層運用

3 曲から「メイン 6 割・残り 2 曲を 2 割ずつ」で配合します。
ただし曲ごとに毎週 3 曲を選び直すと、同じアーティストの声が毎週変わってしまいます。
そこで**二層**に分けます。

| 層 | いつ決めるか | 6:2:2 の対象 | 結果 |
|---|---|---|---|
| **声質（変わらない）** | アーティスト設定時に一度だけ | 声の質感・音域・基本の歌い方 | Suno の Persona として固定 |
| **表現（曲ごと）** | 毎週のブリーフ | 歌い回し・息の混ぜ方・アドリブ・重ね方・加工 | その曲の歌唱指示文 |

- 「光はいつも光の声」のまま、曲ごとに歌い方の表情が変わります
- 「自」のように声の切り貼りが主体のアーティストは、一層目を外して曲ごとに声質も変えてよい（設定書の `vocal.fixed_timbre` で切り替え）
- 6:2:2 の記述は「○○（実在アーティスト）の声 60%」ではなく、**解析シートの形容詞を 6:2:2 で合成した文章**になります。これで声の模倣（DistroKid の禁止事項）にも当たりません

### 合成の例（表現層）

```
メイン（6 割）: 息を多めに混ぜ、フレーズ末を下げて落とす。アドリブは少ない
サブ 1（2 割）: サビで 3 度上のハーモニーを重ねる
サブ 2（2 割）: 語尾に短いしゃくりを入れる

→ 歌唱指示: 「息混じりで、フレーズの終わりは静かに下げて落とす。アドリブは控えめ。
   サビだけ 3 度上のハーモニーを薄く重ね、語尾にごく短いしゃくりを時々入れる」
```

## ルール 3：フレーズの変形（細かく借りるときの上限）

フレーズは近く借りてよい、という方針を安全に運用するため、**似ている要素の数に上限**を設けます。
フレーズは次の 5 要素でできています。

1. リズム骨格
2. 音の輪郭（上がる / 下がる の形）
3. 言葉
4. 楽器
5. 曲中の位置

**ルール**

- 5 要素のうち、**同時に残すのは最大 2 つ**（例：リズム骨格と位置を残し、輪郭・言葉・楽器は変える）
- **輪郭を残すときは、必ず調と音程の幅を変える**（上 → 上 → 下 の形は残して、跳躍の大きさを変える）
- **言葉は常に変える**（カテゴリだけ継承する）

ブリーフ生成時に、この条件を満たす変形案を Claude が 3 つ出し、人が 1 つを選びます。
ブリーフの `phrase_transform.kept` に残した要素を記録し、2 つを超えていたらデータベースの制約で弾きます。

## ルール 4：生成に渡してよいもの・いけないもの

| 渡してよい | 渡してはいけない |
|---|---|
| テーマ、感情の推移、韻の型、音節数 | 歌詞の文章・フレーズそのもの |
| 印象的なワードの**カテゴリ** | 語そのもの |
| フレーズのリズム骨格・輪郭（変形後） | 音程の並び（絶対音名） |
| 楽器リスト、奏法、エフェクトの種類 | ― |
| 声質・歌い方の形容詞（6:2:2 合成文） | 実在アーティスト名、「○○風の声」 |
| BPM、グルーヴの型、転調の型 | ― |

## ルール 5：成績を次週に反映する

配信後の再生数・保存数・スキップ率を、**枠ごとの参考曲に紐づけて**集計します。
「`groove` 枠にこの曲を使ったときは保存率が高い」のような傾向を、次週のランダム選択の**重み**に反映します。
ただし重みを強くしすぎると毎週似た組み合わせになるので、重みの上限は 3 倍までとします。
