# 14. 保管の現状（外付け SSD「DS72」中心・2026-10-14 時点）

管理の見直しに使う一覧。決まりの経緯は `docs/12_decisions.md` の 13・14。

## 1. どこに何があるか

保管庫＝SSD の `Postdog Records/`。「手元」＝ Mac の `~/Eather-Archi/music-label/`。

| もの | 正本（いちばん新しいもの） | 手元の写し | SSD での置き場所 | 作る・書く人 | SSD に入るタイミング |
|---|---|---|---|---|---|

「保管のたび」＝次の 3 つのどれか。SSD がつながっていなければ飛ばし、次につないだときにまとめて追いつく。

| いつ | 何が動くか |
|---|---|
| 毎週の仕上げの最後（火〜木の毎時の自動実行の中） | `run_week.py` → `archive_sync.py` |
| 毎日 3:30 | 定期実行の backup → `archive_sync.py`（と、鍵があれば Cloudflare R2 への予備保管） |
| 手で | `python3 scripts/archive_sync.py`（確認だけなら `--check`） |

## 2. 保管の決まり

| 決まり | 中身 |
|---|---|
| フォルダ名 | アーティスト名。大文字・小文字、全角・半角の違いは同じフォルダとみなし、あればそこへ入れる |
| ファイル名 | `<アーティスト名>_photo.jpg`・`_photo2.jpg`・`_cover.jpg`・`_<配信日>_cover.jpg`・`_<週>_master.wav` |
| 上書き | 中身が同じなら写さない。変わったら前の版を `_old` で 1 つ残す（もっと前の版は残らない） |
| 試験のデータ | 試験用の週（2000-xx-xx）のものは入れない |
| SSD を探す方法 | 名前に「DS72」を含むドライブ。違う名前なら `archive_sync.py --setup /Volumes/<名前>` |

## 3. 見直したほうがよい点

| # | 気になる点 | 起きること | 案 |
|---|---|---|---|
| 1 | 保管が SSD 1 台だけ | 故障・紛失・落下で全部なくなる（Mac の中の写しは一部だけ） | 2 台目の SSD に月 1 回写す／Time Machine／Cloudflare R2 の予備保管（鍵を入れれば毎晩動く） |
| 2 | 管理表を SSD と手元の両方で書き換えられる | 「新しいほう」で決めるので、SSD で書いたあとに、Claude が書き換えた手元の写しを Mac で `git pull` すると、手元のほうが新しい扱いになり、SSD での書き込みが `_old` に回る | 管理表は SSD でだけ書く、と決める。Claude の書き換えは「変更の提案」の行で渡す |
| 3 | 選ばなかったテイクを SSD に入れていない | あとで別のテイクを使いたくなっても、Mac から消えていたら戻せない | 全テイクを `楽曲/<週>/テイク/` に入れる（容量は 1 本あたり MP3 なら数 MB、WAV なら 30〜40MB ほど） |
| 4 | 毎週の記録（ブリーフ・登録シート・歌詞）を SSD に入れていない | Mac が壊れると、どの曲をどの指示で作ったかが分からなくなる | `楽曲/<週>/` にブリーフ・最終歌詞・登録シートも入れる |
| 5 | 配信後の情報（ISRC・配信日・URL）の置き場所が決まっていない | 権利や成績の確認のときに探せない | 管理表に「配信の記録」タブを足す |
| 6 | 古い版は `_old` の 1 つだけ | 2 回作り直すと最初の版が消える | `_old` を日付付きで残す（例 `_2026-10-14`） |
| 7 | SSD の形式 | Mac だけで使うなら APFS が安全。Windows とも使うなら exFAT | 今の形式を確かめる（Finder で SSD を選んで「情報を見る」） |
| 8 | Google の移行前の版 | 古い版が残っていると、どれが正しいか迷う | 移し終えたら、Google 側の名前の先頭に「【旧】」を付けるか消す |
