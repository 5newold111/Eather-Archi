# 14. 保管の現状（ローカル保存（一時保存） → 外付け SSD「DS72」・2026-10-16 時点）

管理の見直しに使う一覧。決まりの経緯は `docs/12_decisions.md` の 13〜16。

## 0. 保管の 2 段構え

| 段 | 場所 | いつ | 入るもの |
|---|---|---|---|
| 1 | Mac のダウンロードの `SUNO楽曲/ローカル保存（一時保存）/<アーティスト名>/` | いつでも（SSD が無くても） | 01_情報・02_写真・03_ジャケット・04_楽曲（公開セット）。ハードリンクなので容量は増えない |
| 2 | SSD の `Postdog Records/` | つながっているとき（無ければ後回し。次につないだときに追いつく） | 1 段目と同じもの ＋ 01_管理表・03_作業書（この 2 つは SSD にだけ。SSD が無いときは書き込みを保留） |
| 予備 | Cloudflare R2 の `label/ssd/` | 毎日 3:30（鍵があるとき） | SSD の中身 |

公開セット＝`02_アーティスト/<名前>/04_楽曲/<週>/` の、配信用の音源（master.wav）・その週のジャケット・その曲の DistroKid 登録シート・選んだテイク・最終の歌詞。
ここを開けば DistroKid に登録できる。

## 1. SSD の中の並び

Finder で番号順に並ぶ。前の並び（管理表・アーティスト情報・写真 など）のフォルダは、次に機械が動いたときに新しい名前へ自動で移す。

```
Postdog Records/
  01_管理表/
      アーティスト情報.xlsx   ← アーティストの正本（オーナーが書く。ここでだけ書く）
      楽曲管理.xlsx           ← 曲の一覧と進み具合（機械が書き直す。オーナー用の欄は消さない）
  02_アーティスト/
      <アーティスト名>/
          01_情報/        設定書（json）・プロフィール（md・json）
          02_写真/        <名前>_photo.jpg・<名前>_photo2.jpg・選ばれたデビュー写真
          03_ジャケット/  <名前>_cover.jpg（デビュー曲）・<名前>_<配信日>_cover.jpg（毎週）
          04_楽曲/
              <週>/       公開セット：<名前>_<週>_master.wav・<名前>_<配信日>_cover.jpg・<名前>_<週>_登録シート.md・選んだテイク・歌詞
  03_作業書/
      デビュー_<日付>/    作業書（PDF）・曲の情報（kit.json）・画像の依頼文
  09_移行前/              Google から移したもの（オーナーが入れる。機械は触らない・R2 にも写さない）
  データベース/            オーナーが作った参考データベース（場所・名前は自由。reference_db.py が探して読む）
```

参考データベースは、名前に「データベース」「database」「DB」「参考」「リファレンス」「ライブラリ」を含むフォルダかファイル（SSD の一番上か Postdog Records の中）。
読み方は `python3 scripts/reference_db.py --show`、取り込んだ結果は `out/reference_db/summary.md`（どの見出しをどう読んだか・枠ごとの曲数）と `digest.md`（傾向）。

## 2. どこに何があるか

「手元」＝ Mac の `~/Eather-Archi/music-label/`。

| もの | 正本 | 手元の写し | SSD での置き場所 | 作る・書く人 | SSD に入るタイミング |
|---|---|---|---|---|---|
| 管理表（アーティスト情報・14 タブ） | SSD だけ | `artists.xlsx` は SSD に無いときに置く見本だけ | `01_管理表/アーティスト情報.xlsx` | オーナー（Excel・Numbers）。機械は「提案」の行だけ足す | 最初の 1 回だけ見本を置く。以後は SSD の正本を書き換える |
| 詰まっているところ（進み具合） | SSD | 同上 | 管理表の「詰まっているところ」タブ | オーナー・Claude | 同上 |
| 楽曲管理（曲名・アーティスト・フェーズ・歌詞・配信の記録） | SSD | — | `01_管理表/楽曲管理.xlsx` | 機械（`song_book.py`）＋オーナー用の欄 | 保管のたび |
| 設定書（自動の流れが読む形） | 手元（管理表から作る） | `templates/artists/<組>.json` | `02_アーティスト/<名前>/01_情報/` | 機械（`artist_book.py pull`） | 保管のたび |
| プロフィール文 | 手元 | `out/profiles/` | `…/01_情報/` | 機械 | 保管のたび |
| アーティスト写真（1・2 枚目） | SSD | `debut_kit/<日付>/images/` | `…/02_写真/` | 機械（`kit_images.py`）→ オーナーが確認 | 作った直後 |
| ジャケット | SSD | `debut_kit/…/images/`・`out/visuals/<組>/cover/<週>/` | `…/03_ジャケット/` | 機械 → 最初の 5 回はオーナーが選ぶ | 仕上げた直後 |
| 楽曲（配信用の音源・選んだテイク・歌詞） | SSD | `out/masters/`・`out/takes/`・`out/briefs/` | `…/04_楽曲/<週>/` | オーナーが Suno で作って置く → 機械が計測・音量調整 | 毎週の仕上げの最後 |
| デビューの作業書・曲の情報・依頼文 | SSD | `debut_kit/<日付>/` | `03_作業書/デビュー_<日付>/` | Claude | 保管のたび |
| 予備保管（SSD の中身の写し） | — | — | Cloudflare R2 の `label/ssd/` | 機械（`backup_r2.py`） | 毎日 3:30（R2 の鍵があるとき） |
| 鍵（OpenAI・R2 など） | 手元だけ | `.env` | 入れない（R2 にも入れない） | オーナー（`setup_keys.py`） | — |
| 決めたこと・使い方・仕組み（プログラム） | GitHub | `docs/`・`scripts/` | 入れていない | Claude | — |
| 毎週の記録（ブリーフ・登録シート・管理画面） | 手元だけ | `out/briefs`・`out/distrokid`・`out/weeks`・`out/dashboard.html` | 歌詞だけ入る | 機械 | — |
| Google のシート・ドキュメント・ドライブの画像 | 移行前の版（もう使わない） | — | `09_移行前/` | オーナーが移す | 手作業 |

「保管のたび」＝次の 3 つのどれか。SSD がつながっていなければ飛ばし、次につないだときにまとめて追いつく。

| いつ | 何が動くか |
|---|---|
| 毎週の仕上げの最後（火〜木の毎時の自動実行の中） | `run_week.py` → `archive_sync.py`（最後に `song_book.py`） |
| 毎日 3:30 | 定期実行の backup → `archive_sync.py` → `backup_r2.py`（R2 の鍵があれば SSD の中身も R2 へ） |
| 手で | `python3 scripts/archive_sync.py`（確認だけなら `--check`） |

## 3. 楽曲管理シート（`01_管理表/楽曲管理.xlsx`）

1 曲 1 行。見出しが紺色の欄は機械が書き直し、茶色の欄はオーナーが書く（書き直しても消さない）。2 枚目のタブ「フェーズの説明」に各段階の意味がある。

| 欄 | 書く人 | 中身 |
|---|---|---|
| 曲 ID | 機械 | デビュー曲は PDR-001〜、毎週の曲は <週>_<組> |
| アーティスト・曲名・曲名の別案 | 機械 | ブリーフ・作業セットから |
| フェーズ | 両方 | 下の 8 段階。機械とオーナーのうち先に進んでいるほうを残す |
| 次にやること | 機械 | フェーズに合わせた次の作業と、誰がやるか |
| 制作週・配信予定日 | 機械・オーナー | |
| BPM・ジャンル・言語・Suno の指示・歌詞 | 機械 | Suno にそのまま貼れる形 |
| 選んだテイク・保管場所（SSD） | 機械 | |
| ISRC・UPC・配信 URL・メモ | オーナー | 配信が始まったら書く |
| 更新日 | 機械 | |

| フェーズ | 誰が進めるか |
|---|---|
| 1 企画 | 自動（ブリーフ） |
| 2 Suno で作曲 | オーナー（テイクを `out/takes/<曲 ID>/` に置く） |
| 3 テイク選び | 最初の 5 回はオーナー |
| 4 音量調整 | 自動 |
| 5 ジャケット | 自動 → 最初の 5 回はオーナーが選ぶ |
| 6 登録の準備 | オーナーが DistroKid に登録 |
| 7 DistroKid 登録済み | オーナーが書き換える |
| 8 配信中 | オーナーが書き換える |

## 4. 保管の決まり

| 決まり | 中身 |
|---|---|
| フォルダ名 | アーティスト名。大文字・小文字、全角・半角の違いは同じフォルダとみなし、あればそこへ入れる |
| ファイル名 | `<名前>_photo.jpg`・`_photo2.jpg`・`_cover.jpg`・`_<配信日>_cover.jpg`・`_<週>_master.wav`・`_<週>_歌詞.txt` |
| 上書き | 中身が同じなら写さない。変わったら前の版を `_old` で 1 つ残す（もっと前の版は残らない） |
| 試験のデータ | 試験用の週（2000-xx-xx）のものは入れない |
| SSD を探す方法 | 名前に「DS72」を含むドライブ。違う名前なら `archive_sync.py --setup /Volumes/<名前>` |
| 管理表を書く場所 | SSD の `01_管理表/アーティスト情報.xlsx` だけ。Claude からの変更は「提案」の行で渡す |

## 5. 見直した点（2026-10-16）

| # | 気になっていた点 | 決めたこと |
|---|---|---|
| 1 | 保管が SSD 1 台だけ | 済：Cloudflare R2 に毎晩写す（鍵は `setup_keys.py --only r2`） |
| 2 | 管理表を SSD と手元の両方で書き換えられる | 済：SSD でだけ書く。手元の `artists.xlsx` は見本だけ |
| 3 | 選ばなかったテイクを SSD に入れていない | 作らない（選び直しには使わない） |
| 4 | 毎週の記録を SSD に入れていない | 済：楽曲管理シートに歌詞・Suno の指示などをまとめ、最終の歌詞は `04_楽曲/<週>/` にも入れる |
| 5 | 配信後の情報（ISRC・配信日・URL）の置き場所 | 済：楽曲管理シートのオーナー用の欄 |
| 6 | 古い版は `_old` の 1 つだけ | 未定（R2 にも写しがあるので、まずはこのまま） |
| 7 | SSD の形式 | 未確認（Mac だけなら APFS、Windows とも使うなら exFAT。Finder で SSD を選んで「情報を見る」） |
| 8 | Google の移行前の版 | `09_移行前/` に入れる。移し終えたら Google 側の名前の先頭に「【旧】」を付けるか消す |
