## 1. フォルダの置き場所 → 非公開の別リポジトリに切り出す（このまま公式サイトに合流させない）

**理由**：公式サイトの公開設定（`.github/workflows/static.yml`）は「リポジトリ全体をそのまま公開する」形になっている。
この作業のプルリクエストの合流先は、そのサイトを公開しているブランチ（`claude/ether-arch-company-site-qfyn98`）。
合流すると、`music-label/` の設定書（アーティストのプロフィール、好きな実在アーティスト名）・戦略資料・データベース設計が
**公式サイトから誰でも見られる状態**になる。最初に決めた「クローズドな環境」と矛盾する。

**やり方**（GitHub で非公開リポジトリを 1 つ作ってから、Mac のターミナルで）

```
# 1. GitHub で New repository → 名前 etherarchi-label → Private → 作成（README などは付けない）
# 2. 今のリポジトリから music-label だけを取り出して、新しいリポジトリに送る
cd ~/Eather-Archi
git fetch origin claude/jolly-edison-bzgnjf
git checkout claude/jolly-edison-bzgnjf
git subtree split --prefix=music-label -b label-only
git push https://github.com/5newold111/etherarchi-label.git label-only:main
# 3. 新しいリポジトリを手元に持ってきて、鍵と作業データを移す
cd ~ && git clone https://github.com/5newold111/etherarchi-label.git
cp ~/Eather-Archi/music-label/.env ~/etherarchi-label/.env
cp -R ~/Eather-Archi/music-label/out ~/etherarchi-label/out 2>/dev/null || true
# 4. 定期実行を入れていたら、新しい場所で登録し直す
cd ~/etherarchi-label && python3 scripts/schedule.py install
```

移したあと、公式サイトのリポジトリのこのプルリクエストは「合流せずに閉じる」。

## 2. SNS のアカウント → まずレーベル単位で 1 組ずつ

**理由**：組ごとに作ると、アカウント作成・本人確認・API の許可・審査が組の数だけ増える（Postdog Records だけで 5 倍、子レーベルを入れると 17 倍）。
YouTube は 1 プロジェクト 1 日 6 本までのアップロード枠もある。最初はレーベルのアカウントで全組を発信し、説明文と動画の中で組の名前を出す。

**伸びた組だけ独立させる**：成長分析で「伸びている（up）」が続いた組は、その組専用のアカウントを作り、鍵の名前の後ろに組の名前を付けて入れる
（例 `YOUTUBE_REFRESH_TOKEN__LIGHT`、`IG_ACCESS_TOKEN__LIGHT`）。投稿の仕組みは、組専用の鍵があればそちらを優先する。

| レーベル | YouTube | Instagram | TikTok |
|---|---|---|---|
| Postdog Records | 1 チャンネル | 1 アカウント | 1 アカウント |
| 子レーベル | 立ち上げるときに、レーベルごとに 1 組ずつ（鍵は `__FOCUS` など） | 同じ | 同じ |

## 27. 参考データベースを、既存の組のこれからの作曲に組ごとに効かせる（2026-10-22）

オーナーが参考データベース（SSD の「データベース」）を作ったので、全体の傾向だけでなく、**組ごとに「この組に近い曲」を割り出して**使う。

- 取り込み（`reference_db.py`。毎週の制作の前にも自動で動く）のたびに、組ごとの近い参考曲を作る：`out/reference_db/artists/<組>.json`・一覧は `out/reference_db/artists.md`
  - 近さ＝設定書のジャンル・特徴語とデータベースのジャンル・タグ・楽器の言葉の重なり（6 割）・テンポ（倍・半分のノリも同じとみる。2.5 割）・声の性別（1.5 割）。日本語の言葉（アコギ・雨・夜 など）は英語に直して比べる
  - 言葉が 1 つも本当に重ならない曲は、テンポと声が合っても近いとみない
  - データベースに **「使う組」の欄**（または メモ）に組の名前（例：TIDEWOOL）を書いた曲は、その組で最優先にする
  - SSD が無いときも、前回の取り込みから作り直す（`python3 scripts/reference_db.py --artists`）
- 使う場所：
  | どこで | どう効くか |
  |---|---|
  | 参考曲の割り当て（`select_references.py`） | 近い曲ほど選ばれやすい（重み 1〜3 倍）。1 曲 1 枠・ボーカル 6:2:2 の決まりはそのまま |
  | ブリーフ作り（`write_brief.py`） | Claude に「この組に近い曲の傾向」（タグ・テンポ・テーマ・楽器・声・オーナーのメモ）を、全体の傾向より重く渡す。実名は伏せる |
  | Suno のスタイル欄（`suno_design.py`） | 近い曲に 2 曲以上出てくる英語のタグで、設定書にまだ無く、禁止・除外に当たらないものを、いちばん後ろに最大 4 つ足す（いちばん弱く効く位置）。止めるときは `templates/suno_options.json` の `use_reference_db` を false |
- 組の音の決まり（設定書）が先で、データベースはその中での好みの寄せ方。実在の名前は Suno にも Claude にも入れない（今までどおり）

## 34. Suno のロボット確認が何度も出て通らない件への対応（2026-10-22）

- 原因の見当：入力のためにページに入れていた仕掛け（翻訳止め・部品の一覧・クリックで教える）が、ロボット確認の小さな画面（Cloudflare の iframe）の中にも入っていた。また、何曲か続けて入れるときは、Gon さんが Create を押す間もシステムが Chrome につながったままだった。ロボット確認は「自動操作の気配」があると何度でも出して通さない
- 直したこと：
  - 仕掛けは一番外の画面だけに入れる（iframe・challenges.cloudflare.com・hCaptcha・reCAPTCHA には入れない）
  - Suno は 1 回の「Suno に入力する」で 1 曲だけ。入れ終わったらすぐにシステムが Chrome から離れ、つながっていない状態で Gon さんが Create を押す。次の曲は少し時間をあけてもう一度押す
- それでも通らないとき：専用の Chrome は使わず、ふだんの Chrome か Safari で `http://localhost:8765/phone`（スマホのページ。Mac でも使える）を開き、「写す」ボタンで Suno に貼る。続けて何曲も作らない

## 93. 歌詞の書き方を DistroKid・Apple Music の歌詞の決まりにそろえる（2026-10-26。オーナーの指示。決定 92 を広げる）

決まり（作るときも、配信サイトに出すときも同じ）：
- 歌詞だけ：歌い手の名前（「Isla:」）・余分な文字（「Intro」「Chorus」・SNS の住所）を入れない
- 繰り返しは書き出す（「Chorus 2x」「(x2)」と書かない）
- 行の頭は大文字。全部大文字・全部小文字にしない（i → I）
- 行末に句読点を付けない。! と ? だけは残す（決定 92 で残していた … と ... も消すことにした）
- 1 行 1 文（長すぎる行にしない）・行の頭と終わりに空白を入れない・空の行は段落（Verse・Chorus など）の間だけ
- 伏せ字にしない（音で伏せているときだけ伏せる）
- 1〜10 の数字は言葉で（英語の行は two、日本語の行は 二。時刻 2:40 や 401 号線はそのまま）
- 標準の綴り（tryna → trying to、gonna → going to、wanna → want to、gotta → got to、kinda → kind of、cuz → because、runnin' → running など）

仕組み：
- scripts/_lyric_rules.py に決まりを 1 か所でまとめた（Claude・Suno に渡す英語の決まり RULES_EN と、整える部品 tidy／tidy_line／split_sentences など）
- 作るとき：write_brief.py の Claude への決まり 16 を書き直し、返ってきた歌詞と核（サビ・決め台詞）を整える。
  Suno の歌詞づくりに貼る指示文にも決まりを足す。Suno が書いた節と合体した歌詞（merge_lyrics.py）、Suno に入れる直前（suno_design.py。オーナーが直した歌詞も）、
  新しいアーティストの「歌詞の試作」（artist_book.py）も同じ決まりで整える
  - Suno に入れる歌詞では、[Verse 1] などの札（Suno への構成の指示）は残す
- 配信サイトに出すとき（store_lyrics.py。決定 52 を広げた）：札・指示を消して段落に分け、上の決まりで整える。加えて
  - 札なしで書かれた「Chorus 2x」「Verse 1:」「Repeat chorus」の行も消す。中身を書いていないサビ（[Chorus] の札だけ）は、前の同じサビを書き出す
  - 1 行に 2 文あれば、文の切れ目で 2 行に分ける（Mr. や U.S.A. のような略語では分けない）
  - 自動で直せないもの（伏せ字・ya や ain't などの言い方・13 語を超える行・Suno が歌詞と違う言葉で歌っているところ）は「歌詞_確かめること.txt」に出す
- 既存楽曲から聞き取った参考曲の歌詞は、原文のまま（決定 87）

- 試験：月 1 の仕事で 6 手順中 2 つが失敗 → 20 時間たつまでは待つ → 失敗した 2 つだけやり直し、1 つ直って 1 つまだ → 次は残りの 1 つだけ、を確かめた

## 114. ジャケットは実在の CD ジャケットの「作り方」を 1 枚ずつ借り、AI っぽさを避ける（2026-10-27。オーナーの指示「候補がどれも AI チック」）

- 原因：候補 6 枚が同じ指示文・参考 3 枚の特徴を混ぜた平均的な方向・「細部まで鮮明に」の指示（描き込みすぎ・つやつやの AI らしさを招く）
- 参考の選び方（cover_refs.py）：その曲で借りた参考曲 → 組が選んだ参考曲 → 組に近い参考データベースの曲 → 組の音とビジュアルの言葉に近い順。
  組に合う参考が 8 枚に足りなければ、組のジャンルで実際に販売されている人気アルバム（Apple のジャンル別の一覧。使えなければ Apple の検索）の
  ジャケットを最大 6 枚読む（Claude が色・画材・構図・光・質感・時代感を言葉にする。1 枚 数円。画像そのものは画像を作る AI に渡さない）
- 候補 1 枚ごとに別の参考 1 枚の「作り方」を借りる（混ぜない）。その絵だけのモチーフは使わないと明記。実在の名前は指示文から消す
- 仕上がりの指示：実際にレーベルが CD・レコードで出したジャケットのように（フィルムの写真か、印刷物のデザイン。粒子・紙の質感・余白・描き込みを抑える）。
  AI らしい見た目（描き込みすぎ・つや・エアブラシ・ネオン・光る粒・霧・浮かぶ物・幻想的な風景・完全な左右対称）は避ける
- Claude の採点の「仕上がり（craft）」で、AI っぽい候補は 1〜2 点にする
- 画像づくりに失敗して候補の記録だけ残ったとき、自動の候補づくりが止まっていたのを直した（画像が 1 枚も無ければ作る）

## 115. ジャケットは曲のワンシーンを切り取る（2026-10-27。オーナーの指示）

## 116. ジャケットには必ずアーティスト名と曲名を入れる（2026-10-27。オーナーの指示）

- いままで文字が入らない場合が 3 つあった：デビュー曲のジャケット（kit_images.py の作り方で、文字を重ねる処理を通らない）・
  書体に無い文字（日本語の曲名など。□ にならないよう文字なしで進めていた）・曲名が未定
- これから：取り込んだ曲を DistroKid の準備に進める前に（publish.advance）、ジャケットの文字を確かめ、入っていなければ入れる（デビュー曲も）。
  入れられないとき（曲名が未定など）は「ジャケット待ち」で止めて理由を出す。文字なしのまま DistroKid の準備には進めない
- 組の書体に無い文字は、日本語も書ける予備の書体（Mac のヒラギノ角ゴシックなど・fonts/ に置いた書体）で入れる
- 曲名を変えて入れ直すときは、文字なしの版（<名前>_notext.jpg）から入れ直す（文字が二重にならない）
- 文字は今までどおり画像を作る AI には書かせない（綴りが DistroKid の登録と必ず同じになるように、仕上げで重ねる。決定 36）
- 試験：英語の曲名・日本語の曲名（予備の書体）・曲名を変えて入れ直し・文字なしのジャケットに入れる・曲名が未定で止める、を確かめた

## 117. ジャケットに本人や物語の人物を、手やシルエットで登場させる（2026-10-28。オーナーの指示）

- 曲のワンシーン 3 つ（決定 115）を振り分ける：1 つ以上はアーティスト本人、1 つは曲の物語に出てくる人物（「君」・助手席の人・友人など）、
  残りは自由（人なし・小物の寄りなど）。どれも顔は写さない（手・背中・シルエット・首から下・肩越しなど）。
  体の写し方と距離（手の寄り・腰から下・遠くのシルエット・肩越し）も場面ごとに変える
- 本人の場面は、アーティスト写真と同じ人に見えるように、管理表のメンバーの見た目（性別・年齢・身長・髪・服・楽器・見える傷やタトゥー）と
  組の「顔の隠し方」（主・副）、「しないこと」を指示に入れる。名前・出身地などは Claude にも画像を作る AI にも渡さない
- 場面の選び方を変えたので、前の選び方で選んだ場面（版 1）は、次にジャケットを作るときに選び直す
- 念のため：Claude が書いた場面や参考の文に実在の名前（組が影響を受けたアーティストなど）が紛れたときは、処理ごと止めずに取り除いてから組み立てる
- 試験：偽の Claude で、本人・物語の人物・人なしの 3 場面になる・本人の場面だけに見た目と顔の隠し方が入る・紛れた実名が消える、を確かめた。本物の画像づくりではまだ
