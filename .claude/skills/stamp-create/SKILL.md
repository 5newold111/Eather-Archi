# スタンプ作成（画像 → 中間カットを補完した透過GIF）

添付画像をもとに、小さく表示しても伝わる、背景が透明な動くGIFスタンプを作る。
キー画像（ポーズの違う原画）の間を補うカットを自動で作り、動きをなめらかにする。

## ルール：足りない情報は必ず聞く（最優先）

作り始める前に、下の「必須の情報」が依頼文に書かれているか確認する。
**1つでも書かれていない項目があれば、勝手に決めずに `AskUserQuestion` で質問する。**
今回の依頼文に書かれていない項目は、過去の依頼で使った値があっても、毎回あらためて聞く。

必須の情報（書かれていなければ必ず質問する）:

| 項目 | 内容 | 質問の選択肢の例 |
|---|---|---|
| 動き | 何をどう動かすか | うなずく（縦）／首をかしげる・揺れる（左右）／跳ねる／ぷにっと伸び縮み |
| 回数 | 1ループで何回動くか | 1回／2回／3回 |
| 長さ | 1ループの秒数 | 約1.5秒／約2.4秒／約3秒 |
| 文字 | 文字を入れるか、文字をどう動かすか | 文字なし／画像内の文字を1文字ずつ拡大縮小／文字を新しく追加（内容も聞く） |

質問するときのコツ:
- 1回の `AskUserQuestion` に最大4問までまとめて聞く。往復の回数を減らすため。
- おすすめの選択肢を先頭にして「（おすすめ）」と付ける。
- 素材の画像が無いときは「素材の画像を添付してください」と頼む。ただし依頼文に「添付がなければゼロから描いてOK」とあれば、ゼロから描いてよい。
- 画像がチャットに表示されているだけで、作業フォルダにファイルとして保存されていないことがある（images フォルダや作業フォルダに見当たらない場合）。そのときは、リポジトリにアップロードするか、もう一度添付してもらうよう頼む。

決まった仕様（依頼文で変更の指示がなければこのまま使う。質問のときに「この仕様で作ります」と一言添える）:
- 背景は透過（白などで塗りつぶさない）。白・薄いグレー・描き込まれた市松模様・黄色などの単色背景は消す
- 240×240px 程度の正方形。白フチを付け、小さく表示しても太くシンプルに見えるようにする
- 8〜15フレームで無限ループ
- ファイルサイズ 1MB 以内（超えたらツールが自動で色数を減らす）

## 作り方

作業中は、ユーザーに「いま何をしているか」を日本語で短く伝える（例：「背景を消して透過にしています」）。
専門用語は言い換える（フレーム＝コマ、パレット＝使う色のセット、減色＝色数を減らす、など）。

1. **素材を確認する**：画像を Read で見る。キー画像（ポーズ違い）が何枚あるか、背景の色、文字の有無と色、文字の位置（画像の上から何割か）を確かめる。
2. **必要なものを入れる**：`pip install pillow numpy scipy -q`
3. **設定ファイルを書く**：`example_config.json` をコピーして作業用フォルダ（scratchpad）に置き、中身を書き換える。項目の意味は下の表のとおり。
4. **実行する**：`python3 .claude/skills/stamp-create/scripts/make_stamp.py 設定ファイル.json`
5. **確認する**：ツールが出す `*_preview.png`（全コマを濃い色の背景に並べた確認用シート）を Read で見る。背景の消し残し・文字の欠け・はみ出し・動きの不自然さがあれば、設定を直して作り直す。
6. **報告する**：下の「完了報告」のとおりに伝える。

### 設定ファイルの項目

| 項目 | 意味 |
|---|---|
| `inputs` | キー画像のパス。0番、1番…の順に番号が付く |
| `output` | 保存先。リポジトリの `assets/gif/英語名.gif` を基本にする |
| `background` | `auto`（四隅の色から自動で判断）または `white` |
| `size` / `margin` | 出力のサイズ（px）と周りの余白の割合。`crop: [x0,y0,x1,y1]` で切り抜き範囲を指定することもできる |
| `outline_px` | 白フチの太さ（240px のとき 3 が目安） |
| `frame_ms` | 1コマの表示時間（ミリ秒）。コマごとに `"ms"` で変えられる |
| `text` | 文字の設定。`enabled`、`color`（文字色のRGB）、`max_y_ratio`（文字がある範囲＝上から何割まで）、`pulse`（拡大縮小の幅）、`cycles`（1ループで何回波打つか） |
| `sequence` | コマの並び。下を参照 |

`sequence` の書き方:
- `{"key": 0}` … キー画像0番をそのまま使う
- `{"tween": [0, 1, 0.5]}` … 0番から1番へ動く途中（0.5＝ちょうど半分）の中間カットを作る
- どのコマにも変形を追加できる：`dx` / `dy`（位置のずらし。dy がマイナスで上へ）、`rot`（回転の角度。下端の中央が軸）、`sx` / `sy`（横・縦の伸び縮み。1.0 が等倍）

### 元の絵にないパーツを描き足すとき（前足・表情の変化・「！」マークなど）

`sequence` の変形だけでは作れない動きは、作業用フォルダに専用のスクリプトを書く。
背景を消す・白フチ・保存・確認の処理は自分で書き直さず、`make_stamp.py` の関数を読み込んで使う。

```python
import sys; sys.path.insert(0, ".claude/skills/stamp-create/scripts")
import make_stamp as ms
fg = ms.remove_background("素材.png")          # 背景を消す
# … PIL の ImageDraw でパーツをコマごとに描き足す（元の絵の輪郭線の色・太さに合わせる）…
frames = [ms.finish(cv, crop, 240, 3) for cv in canvases]   # 切り抜き・縮小・白フチ
ms.save_gif(frames, durations, "assets/gif/名前.gif")       # 減色して保存
ms.contact_sheet(frames, "assets/gif/名前_preview.png")     # 確認用シート
print(ms.verify("assets/gif/名前.gif"))                     # 検証
```

コツ:
- パーツは元の絵の輪郭線の色（こげ茶）と太さに合わせ、塗りは元の絵にある色から選ぶ。
- 表情を変えるときは、消したい線（笑った口など）を周りの色で塗りつぶしてから新しい線を描く。
- 驚き顔は**白目を見せない**（ユーザーの好み）。黒目を少しずつ小さくし（ハイライトは残す）、眉を小さく短くしながら上げて目元を変える。元の黒目は、目の周りの模様の色を測ってその色の単色で塗りつぶしてから描き直す（ぼかしで埋めるとにじみが出る）。
- 前足は**白**で**画面の下から**せり上がらせ、手のひら側を見せる。手のひらは大きめにし、肉球は黒っぽい色（例 RGB 62,50,42。鼻の色より少し濃い）で、大きな肉球1つと指先の小さな肉球3つにする。
- 画面の外から入ってくるパーツは、切り抜き範囲（`crop`）を固定にして、端で切れて見えるようにする。
- 弾んで出てくるマークは、大きさを `0.55 → 1.15 → 0.92 → 1.06 → 1.0` のように行き過ぎてから戻すと元気に見える。一番大きくなるコマで画面からはみ出していないか、確認用シートで確かめる。

### 動きの組み立て例

- **うなずき2回（キー画像2枚：顔を上げた絵0番・下げた絵1番、12コマ×200ms＝2.4秒）**
  `0, 中間(0→1), 1, 1, 中間(1→0), 0, 中間(0→1), 1, 1, 中間(1→0), 0, 0`
- **うなずき（画像1枚だけ）**：`{"key":0}` → `{"key":0,"dy":10,"sy":0.97}` → `{"key":0,"dy":18,"sy":0.95}` → `{"key":0,"dy":10}` → `{"key":0}` を必要な回数くり返す
- **びっくり（画像1枚＋描き足し）**：画面の下から白い前足が頬の横へ（4コマ）→ 黒目と眉が小さくなり、眉が上がり、口が「お」の形へ少しずつ変化（3〜4コマ）→ 体が少し跳ねて「！」が弾んで出現（4〜5コマ）→ 最後のコマを長めに表示
- **跳ねる（画像1枚）**：`sy:0.92, sx:1.05`（しゃがむ）→ `dy:-20`（跳ぶ）→ `dy:-28` → `dy:-20` → 着地 `sy:0.94` → 元に戻る
- **左右に揺れる（画像1枚）**：`rot` を `0 → 6 → 0 → -6 → 0` の順にする
- 1ループの秒数 = コマ数 × `frame_ms`。8〜15コマに収まるように `frame_ms`（120〜250ms）で調整する

## 完了報告（必ず入れる）

- **ファイルサイズ**（バイト数と KB。1MB 以内か）
- **透過が保てているか**（検証結果の `has_transparency_index`（透明色が登録されているか）と `transparent_all_frames`（全コマに透明な部分があるか）が両方 true か。透明な部分の割合も添える）
- コマ数、1ループの秒数、無限ループかどうか
- 保存フォルダ：`SendUserFile` で GIF と確認用シートを送り、「保存フォルダを開いて見せる」代わりにする。保存先のフォルダの場所も書く
- 元の絵から変えた点・気になる点（例：中間カットの動きが小さい、元画像にあった二重線を残している）
- リポジトリに保存した場合はコミットしてプッシュし、プルリクエストの下書きを作って、そのリンクを伝える
